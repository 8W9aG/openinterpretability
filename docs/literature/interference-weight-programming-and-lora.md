# Interference, weight-space programming and LoRA

This page sums up 73 reviews of three areas (#4782): catastrophic interference, weight-space programming and low-rank fine-tuning. It puts them beside the repo's own tests of whether a VERIFIED explanation keeps when the weights change. It says what the two bodies of evidence mean together, and which experiments are still open.

The reviews are in four sections of the [literature index](README.md): interference and forgetting, weight-space programming and fast weights, LoRA and low-rank fine-tuning, and bridges. Each page reads its source and says what it did not read. This page cites the pages and the repo's papers, not the sources, so each number here has a page to check.

## The question that joins the areas

A change to a network's weights can break what the network already does. The interference papers ask when that happens. The weight-space programming papers write functions into weights directly, and each must avoid the same damage. LoRA writes a low-rank update into frozen weights, so it is the simplest case of both. For this repo, the three areas ask one question: when the weights change, does a VERIFIED explanation of a unit stay true?

The literature measures the answer almost always by outputs: task accuracy, benchmark scores or a KL divergence. Few of the 73 reviews look at units inside a language model across a fine-tune. [Prakash et al.](fine-tuning-enhances-entity-tracking.md) test 72 attention heads on one task. [Jain et al.](fine-tuning-wrappers.md) prune a few neurons to bring back a capability. [Minder et al.](crosscoder-chat-tuning.md) compare dictionary latents. None of them asks whether a tested explanation of a native neuron stays true. The repo's keep tests fill that gap.

## What the literature found

### Shared weights cause interference, and the remedies guard outputs

- **The cause is overlap.** Shared, overlapping weights make a network forget suddenly ([French, 1999](catastrophic-forgetting-connectionist.md)). Focused learning of one new fact damages related knowledge where the answers differ ([Complementary Learning Systems](complementary-learning-systems.md)). In knowledge editing, a rank-one edit disturbs each other fact in proportion to the overlap of their MLP keys ([Knowledge in Superposition](knowledge-in-superposition.md)). Those keys are neuron activations.
- **The remedies fall into five families**: regularisation, replay, optimisation, representation and architecture ([Wang et al., 2024](comprehensive-continual-learning-survey.md)). EWC and Synaptic Intelligence slow the weights that an importance score rates high ([EWC](elastic-weight-consolidation.md), [SI](synaptic-intelligence.md)). Rehearsal and distillation keep old outputs ([Robins, 1995](rehearsal-and-pseudorehearsal.md), [Learning without Forgetting](learning-without-forgetting.md)). OGD and GEM project each update so that old outputs or old losses do not change ([OGD](orthogonal-gradient-descent.md), [GEM](gradient-episodic-memory.md)). PackNet and HAT freeze the weights or units of old tasks ([PackNet](packnet.md), [HAT](hard-attention-to-the-task.md)).
- **Almost every remedy guards outputs, not units.** The OGD page notes that holding outputs fixed does not hold hidden units fixed. HAT is the closest method to the neuron grain, but a frozen unit's inputs can still change. [Progressive Neural Networks](progressive-neural-networks.md) forget nothing only because old units never read new ones. In a transformer, a change at one layer changes the input of every later layer.
- **Some forgetting is not lost knowledge.** Fine-tuning can change which task the model infers rather than remove a capability ([Implicit Inference](implicit-inference-forgetting.md)). Much of a drop on an old task is lost alignment, and a short recovery tune restores it ([Spurious Forgetting](spurious-forgetting.md)). Small-learning-rate fine-tuning leaves capabilities in place under a thin "wrapper" ([Jain et al., 2024](fine-tuning-wrappers.md)).

### Weights alone can be read only where each weight has a stated meaning

- **Fast weights and linear attention are memories that activations write** ([Schlag et al., 2021](linear-transformers-fast-weight-programmers.md), [Ba et al., 2016](fast-weights-recent-past.md)). Test-time training and Titans keep part of the state out of the checkpoint ([TTT](test-time-training-layers.md), [Titans](titans-test-time-memory.md), [End-to-end TTT](end-to-end-test-time-training.md)). So a rule that needs context is not in the weights alone.
- **Weights read cleanly where a construction gives each weight a meaning.** Compiled transformers are one example ([Tracr](tracr.md), [ALTA](alta.md)). A hand-built gradient-descent layer is another ([von Oswald et al., 2023](in-context-learning-by-gradient-descent.md)). So are a pairwise energy ([Classical Energies](classical-energies-reasoning.md)) and sparse written fact tables ([Ok and Lee, 2026](weight-space-programming-without-transformers.md)). In a trained model, a frontier LLM names copying heads from weights alone ([Sparks of Weight-Space Programming](rikiyat-weight-space-programming.md)). But it needs activations to tell a sycophantic model from an honest one.
- **Programs written into weights interfere less when they use their own capacity.** Exact arithmetic compiled onto added residual wires reaches 97–100%, where LoRA reaches 42–62% ([A CPU Inside an LLM](cpu-inside-an-llm.md)). Removing one line from a written fact table changes far fewer answers than removing one from a written transformer (Ok and Lee).

### Low-rank fine-tuning is low-dimensional, not local

- **A few hundred random directions reach most of a fine-tune's gain** ([Li et al., 2018](intrinsic-dimension-objective-landscapes.md), [Aghajanyan et al., 2021](intrinsic-dimensionality-fine-tuning.md)). But each random direction spreads over every weight. So a low-dimensional change can move every unit a little.
- **LoRA learns less and forgets less than full fine-tuning**, by benchmarks ([Biderman et al., 2024](lora-learns-less-forgets-less.md)). It matches full fine-tuning in loss only when it adapts the MLP too ([LoRA Without Regret](lora-without-regret.md)). So an adapter that matches full fine-tuning changes the weights of the neurons the registry explains.
- **LoRA's update has its own structure.** It amplifies directions that the weight holds but does not emphasise ([Hu et al., 2021](lora-low-rank-adaptation.md)). It adds "intruder" singular vectors unlike any pre-trained one ([Illusion of Equivalence](lora-illusion-of-equivalence.md)). DoRA splits each weight into one magnitude per output feature and a direction ([DoRA](dora-weight-decomposed-lora.md)). For a gated MLP, that magnitude is one scalar per neuron.
- **A composed or merged update has terms that no task trained.** LoraHub's product of summed factors adds cross terms ([LoraHub](lorahub.md)). TIES, task singular vectors and tangent-space fine-tuning each reduce interference between merged task vectors ([TIES](ties-merging.md), [TSV](task-singular-vectors.md), [Ortiz-Jiménez et al., 2023](tangent-space-task-arithmetic.md)). None of these papers measures a unit.

### Edits keep the units below them by construction

ROME and MEMIT write closed-form updates into middle MLP layers ([ROME](locating-editing-factual-associations.md), [MEMIT](memit.md)). Units at or below the lowest edited layer see the same input as before, so only the units above it can change. Sequential edits first forget slowly and then collapse, after 100 to 1,000 ROME edits ([Gupta et al., 2024](editing-at-scale-forgetting.md)). AlphaEdit confines each edit to the null space of preserved keys, and stays at 98.90 efficacy after 2,000 edits where MEMIT falls to 65.65 ([AlphaEdit](alphaedit.md)). LoReFT edits the residual stream and leaves every weight alone ([ReFT](reft-representation-finetuning.md)).

## What the repo's keep tests found

The repo has eight studies of what a weight change does to its VERIFIED explanations. Most of them re-run each explanation's own adversarial probes on the changed model. Taken together, they give five results.

1. **About one explanation in five fails under any change of this size.** Instruction tuning keeps 298 of 361 on Qwen2.5-0.5B ([random-change-keep](../../papers/random-change-keep/README.md)). A random change of the same norm keeps 296 to 301. NF4 rounding keeps 281 of 362, and its random null keeps 283 to 294 ([nf4-keep](../../papers/nf4-keep/README.md)). One narrow fine-tune costs 66, about as many as instruction tuning ([sequential-tuning](../../papers/sequential-tuning/README.md)). The literature's claim that a general instruction tune forgets little ([Luo et al., 2023](llm-continual-fine-tuning-forgetting.md)) holds at the unit grain too. But on Qwen2.5-0.5B, the tuning breaks no more explanations than random noise of its size.
2. **The same poles fail under every change, and they sit near a review gate.** The instruct change and its random null share 30 to 32 flips per seed, against about 11 by chance. NF4's flips overlap with the instruct flips. The first narrow stage shares 28 flips with instruction tuning, against 11 by chance. In Pythia-70m's training, 18 of 23 late failures are within two probes of a gate ([neuron-development](../../papers/neuron-development/README.md)). So the keep test measures, in large part, how close a pole was to failing on the base model. #6398 reports each flip's margin.
3. **Importance scores don't predict which poles fail.** The diagonal Fisher, the basis of EWC, separates keeps from fails with an AUC of 0.475, against 0.523 under a shuffled null ([fisher-keep](../../papers/fisher-keep/README.md)). The base-to-instruct KL at each pole, the predictor that [RL's Razor](rls-razor.md) proposes, gives 0.49 to 0.54. At a fixed activation scale, a higher input Fisher goes with a larger change, which is the opposite of what EWC assumes.
4. **Much of the measured loss is format, and much of it churns.** Inside the chat template, the template alone costs the base model 76 explanations, and the tuning costs a net 19 ([template-or-tuning](../../papers/template-or-tuning/README.md)). Across three narrow stages, many explanations fail at one stage and pass again at a later one. This fits [Spurious Forgetting](spurious-forgetting.md) and [Implicit Inference](implicit-inference-forgetting.md): a lost score need not be a lost function.
5. **The explained neurons are what tuning keeps, not what it changes.** Take all VERIFIED poles of one layer at their base-model activations, inside the instruct model. They close a median 0.2% of the output gap, about their share by number ([instruct-difference](../../papers/instruct-difference/README.md)). This agrees with [Prakash et al.](fine-tuning-enhances-entity-tracking.md): tuning enhances mechanisms that exist, and the parts that change are elsewhere.

Two more studies bear on weight-space reading. Only 17.8% of the 826 VERIFIED explanations are token-set rules that a weight-only check could test ([token-set-ceiling](../../papers/token-set-ceiling/README.md)). That ceiling agrees with the fast-weight and test-time-training papers. And a neuron's explanation rests on its largest input weights: half the explanations pass with a tenth of those weights left ([pruning-keep](../../papers/pruning-keep/README.md)). PackNet's finding, that spare capacity is spread across units, fits this too.

## What the two bodies of evidence mean together

**A keep share needs a matched random change and a margin beside it.** The literature reports forgetting as a fall in a score. In the repo's evidence, a fall in the keep share comes mostly from the poles that were near a gate. A change of the same norm in random directions causes it too. So a keep share alone cannot say that a change damaged a mechanism. It needs a random change of the same norm beside it (#6814, #6842). It also needs each flip's margin, and a re-test of the flips near a gate (#6398).

**Weight importance is the wrong tool for protecting explanations.** EWC, SI, AdaLoRA and CurvDelta each rank weights by an importance score. The Fisher result says that such a score does not pick the poles that fail. A method that names the units directly does not need a prediction. OGD, GEM and AlphaEdit already project updates off protected directions. The protected set can be the VERIFIED poles' own activation gradients. #6891 tests this.

**LoRA is the change the repo has not measured.** The literature says LoRA forgets less by benchmarks, and that it must adapt the MLP to match full fine-tuning. Both claims predict an effect on neurons, and no paper measures it. The repo's keep test can, with ReFT as an arm that leaves every pole weight alone. #6890 tests this.

**Interference follows shared capacity, so explanations could predict it.** The editing papers find that interference grows with the overlap of MLP keys, which are neuron activations. Compiled programs on their own wires interfere least. So two changes that run through the same VERIFIED poles should interfere more than two that do not. The interference report (#5230) re-tests units after a change. The traffic map (#5231) and the rank-one edit study (#5362) ask whether shared poles predict the damage.

**Weight-only checks have a ceiling of about one explanation in five.** Every weight-space paper that reads weights cleanly has a construction that gives each weight a meaning. Trained transformers have none. Context rules live partly in activations. So weight reading can be a cheap first check for token-set poles (#3446), but not a substitute for the probes.

## Limits of this synthesis

- **The keep tests cover few models.** Most numbers come from Qwen2.5-0.5B, some from Qwen2.5-1.5B and Pythia-70m. On Qwen2.5-1.5B, random changes keep more poles than the instruct change (72 or 73 against 65), so result 1 may not hold at other sizes.
- **The literature numbers are from single runs.** Many reviews note one seed per setting, or settings chosen on test data. This page repeats their numbers as each page reports them.
- **The keep test is one measure.** It asks whether an explanation still passes its own probes. A pole can keep its explanation while its activations move a lot: pruned poles keep at a median correlation of 0.54.
