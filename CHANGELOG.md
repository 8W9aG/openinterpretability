# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/).

The project has two version numbers:

- **Package version** (`openinterp.__version__`): the code. Bump it in `openinterp/__init__.py`, which `pyproject.toml` reads.
- **Protocol version** (`openinterp.core.schemas.PROTOCOL_VERSION`): the review decision rule. It is stored in every verdict and documented in `docs/PROTOCOL.md` §6. A protocol change always needs a package release too, but not the other way round.

## [Unreleased]

### Added

- **Scans on Apple's Neural Engine when the GPU is busy** (`openinterp/harness/ane/`, `openinterp/harness/scan_backend.py`, `docs/experiments.md` Devices and Caches, `docs/analyses/ane-feasibility.md`). The device planner's order is now MPS, then the ANE, then the CPU. With the GPU busy and the ANE free, a GPT-2 or Qwen2 scan's forward pass runs on the ANE through Core ML. The rest runs on the CPU. `--device ane` asks for it. The pass is written again for the ANE, which computes in fp16 and gets `pow`, `silu` and small matmul products wrong. In fp32 it agrees with HF to 1e-5. The scan then measures each pole's strongest candidates again on the CPU (the top 60, and any within 6% of the 20th, at most 120). So the top examples and scale that `reproduce` checks are exact. On `corpus.jsonl` that rule found the exact top 20 for every neuron of three layers. Converted models are cached in `~/.cache/openinterp/coreml`, once per machine, until the model, the conversion code, coremltools, torch or macOS changes. Each new entry is checked against fp32. On GPT-2 L5 with the GPU busy, an audit took 55 s, against 77 s on the CPU, with the same top examples. `RunEnvironment` has a new optional field, `scan_backend` (`coreml-ane`). A scan on the ANE has its own scan-cache entries. `LabelPass` moved to `harness/annotations.py`. New dependency on Apple-silicon Macs: `coremltools` (BSD-3-Clause).
- **Device planner: `--device auto` uses Apple's GPU only when it is free** (`openinterp/harness/devices.py`, `docs/experiments.md` Devices, from TODO, Performance). A process that runs a model on MPS keeps a lease in `~/.cache/openinterp/devices/mps/`. With `--device auto`, a job runs on the CPU and says why in two cases. One is when it finds another job's lease. The other is when the GPU is more than 50% busy over about 2 s (`ioreg`). `--device mps` still shares the GPU. The 50% threshold is provisional, until a measurement of jobs that share the GPU sets it. Commands now take about 2 s longer to choose MPS, for the utilization readings. If the GPU fails during a command (an error that names MPS, in a process that ran on it), the command runs again from the start on the CPU, in a new process, once.
- **`openinterp corpus --detect-code`: programming languages for unlabelled corpora** (`openinterp/codeid.py`, `docs/analyses/code-detection.md`, `scripts/code_detection.py`, from TODO, Analyses per experiment). The option labels each document's `code_language` with Google's Magika. It labels a document only at confidence ≥ 0.8, and only with one of the github-code preset's 30 language names (`corpus_presets.GITHUB_CODE_LANGUAGES`). So the `programming language` and syntax label sets work on corpora like the Pile, which mixes GitHub files into prose. The source sidecar records the detector (`code_detector`), and `--same-as` detects again. The analysis compared Magika with go-enry (GitHub Linguist), a CodeBERTa language classifier and Pygments. Magika was the most accurate on 1,000 github-code files (91.5% whole, 70% at 200 characters). It was the only one that labelled none of 300 prose documents. On the registry's pile-10k corpus it labels 37 of 500 documents: 17 GitHub files, 10 Stack Exchange posts, and 10 pandoc Markdown or TeX documents. New dependency: `magika` (Apache-2.0, with onnxruntime).
- **`mixed-v7`, which `mixed` now names: detected labels in every experiment's corpus** (`openinterp/blends.py`). It has v6's presets and weights. Each part without exact labels now gets detected ones, as `--detect-lang` and `--detect-code` give them. Before, only Wikipedia's and FineWeb-2's documents had a language, and only github-code's had a programming language. On a 500-document build (seed 4101513517), 426 documents have a language, against 103 in v6. Another 25 outside github-code have a programming language: the Pile's code, Python in chat answers, and TeX in maths posts. Released versions (`NO_DETECTION`) keep their bytes, so records scanned on them still rebuild. Building the corpus takes a few seconds longer.
- **Zenodo concept DOI** (`CITATION.cff`, `README.md`). Zenodo archived the 0.0.18 release. The concept DOI, 10.5281/zenodo.24150022, names every version. It is now `doi:` in `CITATION.cff`, and the README has its badge and names it in *Citing*.
- **The checkpoint test of the push, calibrated on small models** (`papers/why-neurons-rest/README.md`, `scripts/train_resting.py --save-every`, `scripts/pretrained_push.py small`, from TODO, Protocol and science). Small GELU and ReLU runs saved a checkpoint every 250 steps, and the `pythia` test read them. There the push points down in 24 and 26 of 27 layers and checkpoints. Its sign matches each neuron's next move for 55%–58% of neurons. At Pythia-70m's checkpoints it points down in 13 of 30, at chance. So Pythia's push is weaker or less steady, or its far-apart checkpoints hide it. The offset, output and split runs now have a second seed, and each agrees with the first.
- **The pull on the mean output goes through the final LayerNorm and dropout** (`papers/why-neurons-rest/README.md`, `scripts/train_resting.py`, `scripts/pretrained_push.py`, from TODO, Protocol and science). With dropout at 0, the loss still pulls each MLP's mean output toward 0, but more weakly. ReLU's cosine falls from +0.072 to +0.043 on two seeds. New runs close one route at a time. The final LayerNorm and dropout each make the pull alone, and the block LayerNorms don't. With every route closed the pull is 0, and the spread term keeps the push on ReLU's rest at the same pace. The earlier test centred every norm but kept dropout, so it couldn't rule LayerNorm out. New conditions: `relu_dropout_0`, `relu_norms_centred_dropout_0`, `relu_all_norms_centred_dropout_0` and `relu_final_norm_centred_dropout_0`. A new script, `scripts/pretrained_push.py`, records the rest and the push terms of pretrained models with no optimizer step. Its `gpt2` command reads trained GPT-2 small, and its `pythia` command reads Pythia-70m's training checkpoints. GPT-2's terms have the small GELU models' signs but cancel. Pythia's push points down in only a few layers. The ReLU, GELU, norm and no-dropout offset runs now have a second seed.
- **Shell linter** (`Makefile`, `.github/workflows/ci.yml`, `pyproject.toml`). `make shell` runs ShellCheck on every tracked `.sh` file. `make lint` and CI run it. The `shellcheck-py` dev dependency supplies the binary, so `uv sync` installs it. Both scripts pass already.

### Added

- **A registry dashboard on the home page** (`builder/dashboard.py`, `templates/_dashboard.html`, from TODO, Site). Three static SVG charts of experiment verdicts sit below the totals. The first shows the experiments of each day, stacked by verdict, and the share of all experiments to that day that were VERIFIED. Above 120 days, it counts by week. The second shows one bar of verdicts for each model. The third shows a small chart for each model, with a column of verdicts for each layer. Every layer has a slot, so a layer with no experiments shows as a gap. Each chart has a table of its values. The charts count each experiment, repeats too, so they show verdicts and not unit statuses. They leave out dictionary latents, because those are a baseline. - **Signing keys have validity windows, and a revoked key keeps its old signatures** (`openinterp/signing.py`, `openinterp signatures`, `SECURITY.md`, from TODO, Merge verification). Each key in `.github/allowed_signers` now has a `valid-after` option, the UTC day the key was added. To revoke a key, a maintainer adds `valid-before` at the start of its exposure, and keeps the key's line. A signature is checked at the time it landed on `main`, not at the time of the check. That time is the committer date of the newest first-parent commit that added or changed the record or its `.sig` file. So records that landed before the exposure stay trusted. `openinterp reproduce` re-runs a record whose signature landed outside its key's window, and reports why, in place of a failure. `openinterp signatures` lists those records, and `--paths-only` gives paths for `reproduce --include-signed`. An expired key no longer signs new records. The nightly job fetches all of `main`'s history, because it needs the landing times. All 2,192 signatures in the registry are trusted under the new windows. If the second key were revoked from 5 November, 203 records would be reproduced.

- **Syntax paper follow-ups** (`papers/syntax-positive-controls/README.md`, from TODO, Analyses per experiment). GPT-2 closes the rest of its open round brackets with later tokens, and without L2 N676+ it stops after one closer. The head L3H5 carries the pole's signal to the closer, and then to L8 N689+. Four early heads (L0H10, L1H3, L2H10 and L3H10) read the closers and take part in an exact count, which holds up to depth 6. The extra closer that the paper's chain shows at depth 4 comes from steps that the chain forced. The model counts a rare packed closer, such as `))))`, less sharply. No round-depth pole responds to curly brackets that hold a block. The best round-depth poles of Qwen2.5 don't count depth, also at 128-token windows. New scripts: `syntax_followups.py`, `syntax_close_paths.py`, `syntax_close_states.py`, `syntax_close_readers.py` and `syntax_close_match.py`, and `syntax_controls.py` takes `--window`. Records: L9 N340+ and Qwen2.5-0.5B L21 N953− are VERIFIED, and L3H5 is NEEDS_REVISION. Papers are now exempt from the 500-line limit.

- **Where the push on the rest comes from** (`papers/why-neurons-rest/README.md`, `scripts/train_resting.py`, `scripts/resting_push.py`, from TODO, Protocol and science). Held at the same rest of 0, softplus, ReLU and leaky ReLU at slope 0.1 get the same push on two seeds. So the depth that a neuron reaches sets most of the order, not the activation. The push has two terms. When a neuron's mean output is large, its output's push points down. A weak pull of the loss on the MLP's mean output toward 0 is one cause, and it holds in every window of every run. When the mean output is small, as for GELU and SiLU, the tokens on the steep part of the activation carry the push down. Adding a constant to the output swaps ReLU's and GELU's patterns and depths. Held at deeper rests, ReLU's push dies by −2, while softplus keeps most of it at −4. So softplus rests about twice as deep as its push predicts. Leaky ReLU at slope 0.1 is pushed back up at −1, where its mean output turns negative. LayerNorm doesn't cause the pull. New conditions hold any activation at a fixed rest, centre or shift its output, or centre the LayerNorms' input. `--push-part` labels the push rows of a rerun, and the push recorder moved into `scripts/resting_push.py`. No rule changes.

- **Bandit's security checks in `make lint`** (from TODO, Code quality and tooling). Ruff's `S` rules are a port of Bandit, so `ruff check` runs them with no new tool. `pyproject.toml` ignores three rules that only add noise here. S311 flags the random generators, but they seed experiments, not secrets. S603 and S607 flag subprocess calls, but each passes a list and runs a tool on PATH. - **`CONTRIBUTING.md`, `SECURITY.md` and `CITATION.cff`** (from TODO, Housekeeping). `CONTRIBUTING.md` is a short map of the ways to contribute and the rules for pull requests and style, and links the pages that hold the detail. `SECURITY.md` says how to report a problem privately, with GitHub's private vulnerability reporting. It has no version, because Zenodo takes the version from each GitHub release and gives it its own DOI. So the `release` skill now publishes a GitHub release from each tag (step 10). The README links all three, and `make ste` checks the two Markdown files.

### Added

The `fineweb-2` preset samples `HuggingFaceFW/fineweb-2` (ODC-By) in 22 languages besides English, across 12 scripts, with an equal share each. It includes pairs that share a script (Spanish and Portuguese, Russian and Ukrainian, Arabic and Persian). - **A public benchmark for explanation tools** (`openinterp benchmark`, `openinterp/benchmark.py`, `benchmark/v1/`, `docs/benchmark.md`, from TODO, Scope expansion). v1 has 1,253 native neuron poles of Qwen2.5-0.5B, GPT-2 and Qwen2.5-1.5B. The test split is sealed: 5,153 fresh probes, 20 for each unit from a reviewer that had not reviewed it. 14 units had under 3 probes of a label. For each, a second fresh reviewer wrote 20 more, with a mix that leans to the missing label. Two GPT-2 negative poles needed a third set. L7 N2511− fires on almost every token, so it needed a fourth set of very short texts. `docs/benchmark.md` now describes this step. The registry baseline is not scored yet (TODO, Scope expansion). - **The site is served at [open-interpretability.com](https://open-interpretability.com/)** (from TODO, Site). `[project.urls] Homepage` in `pyproject.toml` holds the URL. The README, `docs/PROTOCOL.md`, `docs/development.md` and the `land-experiment` and `write-paper` skills link the site.

- **Streaming onto a CUDA GPU** (`--memory stream` or `auto` with `--device cuda`, `openinterp/harness/memory.py`, from TODO, Performance). The embeddings, final norm and head stay on the GPU, and each layer is copied there when a pass reaches it. `--memory auto` plans with the GPU's free memory. Each tensor is sent in the checkpoint's dtype and converted on the GPU. A float32 Qwen2.5-0.5B pass then took 0.66 s on an RTX 4070 Ti, against 2.8 s converted first. Qwen2.5-3B in float32 (about 14.5 GB) streamed onto a GPU with 9.1 GB free, and a 5,000-token audit took 167 s. Its activations matched the CPU's within 2.4e-6 of their peak. `tests/test_cuda_streaming.py` runs where CUDA is.

- **openinterp's own experts forward for mixture-of-experts models** (`openinterp/harness/moe.py`, from TODO, Models and Performance). It is registered with transformers' `ExpertsInterface` and selected when an MoE model loads. A record pins it (`environment.experts_implementation`). Each expert's hidden activation passes through a per-thread hook before its down projection, where expert neurons will be read. It matches `eager` on seven architectures (`tests/test_moe.py`), and transformers' default `grouped_mm` on Granite 3.0 1B-A400M to 3e-5. Streamed, it reads only the routed experts' slices (`OpenCheckpoint.slice`). A streamed one-token Granite pass read 1.41 GB, not 4.78 GB.

- **Experiment pages say where each step ran** (`_experiment.html`). A "Ran on" row gives the scan's and the review's device, and says when one streamed from disk.

- **How to audit neurons in mixture-of-experts models** (`docs/moe.md`, `scripts/moe_experts_check.py`, from TODO, Models). An expert neuron pole is a new unit kind, `L<layer>/E<expert>/N<idx>-<pole>`. Its strength is the routing weight times its hidden activation, 0 where the router doesn't send the token. Interventions edit it inside the expert on routed tokens and never force the routing. The harness will read it through its own forward, registered with transformers' `ExpertsInterface`, which about 60 MoE architectures use. On tiny random models of seven of them, that forward matches `eager` to within 1e-6. Nothing is built yet. The steps are in TODO, Models.

- **Records say when a run streamed** (`RunEnvironment.streamed`, from TODO, Performance). It is true when the decoder layers were read from disk on each pass, and unset otherwise, as in older records.

- **A memory benchmark at each release** (`scripts/memory_benchmark.py`, `release` skill step 5, from TODO, Performance). It scans and reviews GPT-2 and Qwen2.5-0.5B, 20,000 tokens each, and reads each command's peak resident memory. It fails if a peak is more than 25% above `scripts/memory_baseline.json`. - **A streaming mode for models larger than memory** (`--memory auto|normal|stream`, `openinterp/harness/memory.py`, from TODO, Performance). In streaming mode the decoder layers stay in the checkpoint's files on disk. Each forward pass reads a layer when it reaches it and frees it after. So a model runs in about one layer's memory, slowly. `auto`, the default, streams only when the weights at the chosen dtype, plus 3 GB, exceed free RAM and swap. `$OPENINTERP_MEMORY_GB` plans for less. The numbers are the same as a normal load's, so streamed records reproduce. Under a 1 GB budget, a streamed Qwen2.5-0.5B audit peaked at 1.5 GB, against 2.0 GB of weights. No rule changes.

- **The round-depth poles of GPT-2 through the protocol** (`papers/syntax-positive-controls/README.md`, *Through the protocol*, from TODO, Analyses per experiment). L2 N676+ has a revised claim: open round and square brackets are strong, and curly and angle brackets are weak. It is VERIFIED (1.00) on its second review. Its first review failed only because its hard negatives were too alike. L2 N1195+, L3 N695+ and L8 N689+ are VERIFIED (0.96, 0.92, 0.92). L9 N340+ is NEEDS_REVISION (0.89): it fires on function words inside an open round bracket, and its lookahead claim did not hold. All five scanned the `github-code` sample that the first L2 N676+ record scanned. No rule changes.

- **The push that deepens the rest** (`papers/why-neurons-rest/README.md`, `scripts/train_resting.py --push-every`, from TODO, Protocol and science). Each training run can now record, at every step, the gradient on each neuron's rest and how far the step moves it. The push points down on only about half of single steps, but its mean over 100 steps points down for each one-sided activation. Its size, as mean over RMS, gives the order of depth. Softplus is first, then ReLU, GELU and leaky ReLU at slope 0.01, then leaky ReLU at slope 0.1, SiLU and tanh. The weights carry 97%–99% of the movement. The push is measured where each run rests, so it doesn't yet show that the activation sets it. Also adds leaky ReLU at slope 0.01, which rests like ReLU, and second seeds for softplus, leaky ReLU, SiLU, SGD and the AdamW rates. No rule changes.

- **A JSON, JSONL and YAML linter in `make lint` and CI** (`scripts/check_data_files.py`, `.yamllint.yml`, from TODO, Code quality and tooling). JSON files and notebooks must be UTF-8, parse, have no duplicate keys and end with a newline. A JSONL file has one value on each line and no blank lines. yamllint checks the YAML files and the front matter of Markdown files, with a line limit of 100 as for ruff. The front matter has no line limit. The records under `wiki/` are exempt, because `openinterp check` validates them and they are write-once. Three long lines in the workflows and a Vale rule are now shorter.

- **Proven-dead neuron poles count as verified** (`openinterp/harness/dead.py`). When a random draw stops because the pole never fires on the scan, the weights are checked. The norm before the MLP keeps its input inside a ball of radius √d, so a neuron's pre-activation lies in (c − R, c + R). For LayerNorm, c = w·β + b and R = √d·‖centred(w⊙γ)‖. In an ungated MLP with GELU or SiLU, c + R ≤ 0 proves the positive pole dead, and c − R ≥ 0 proves the negative pole dead. ReLU's negative pole is always dead. A gated (SwiGLU) pole is proven dead only when one of its reads is exactly zero. The draw records `proven_dead` and the bound (`dead_bound`). The planner and the site's model cards then count that neuron as verified towards the explore target. A pole that is only silent on the corpus doesn't count. On GPT-2 small, no pole is proven dead today: every bound is at least 0.92 R away from 0.

All 25 continuations decode as one left-padded batch with the model's cache, about 3 s on CPU for Qwen2.5-0.5B, recorded as the `steering` cost stage. Like the Patchscope readout, they are taken after the proposer has answered and appear in neither agent's prompt. Wiki pages show a table per experiment, and site pages show each prompt's continuations side by side, ablated through ×4. Text identical to the baseline faded. On L14/N2611+ (crops), clamping at ×1 changes "Once upon a time,". A girl named Lily becomes a farmer who wants his crops healthy and strong. At ×4 "The report concluded that" ends in the worst drought in the region's history. Ablation leaves all five continuations unchanged. Heads get no samples, since a head has no single "high" setting. Existing records have none until their units are audited again. Reported, not gated. The protocol version is unchanged.
- **Patchscope readout of a unit's output direction.** `openinterp audit` now records the model's own description of what a neuron pole or dictionary latent writes, with no examples (`NeuronAuditSubmission.patchscope`). The direction (a pole's signed `w_out`, or a latent's decoder row) replaces the residual stream after a layer's block at the `?` of an inspection prompt. It is scaled to 1, 2 and 4 times the norm it replaces. The model then continues greedily (Ghandeharioun et al., 2024, Chen et al., 2024). There are two prompts, a few-shot `word: category` list and `The meaning of the word "?" is`. Each is read at the unit's own layer and at layer 2. Every reading is paired with a fixed random direction injected the same way, so text that comes from the prompt shows up in both. On Qwen2.5-0.5B the category prompt at layer 2 names the concept of several VERIFIED poles where the control does not. It gives *crop* for L14/N2611+ (crops) and *newspaper* for L5/N4579− (periodicals). It also gives *official* for L3/N3738− (*official*) and *culture* for L5/N2131− (art and folk culture). Poles from layer 17 up, injected at their own layer, mostly read back the control's text. The readout is taken only after the proposer has answered, in both the one-step and the `--evidence`/`--hypothesis` flow. It is absent from evidence files and appears in neither agent's prompt. That makes it a blind baseline for a later comparison with the agent's hypotheses. It takes about 5–8 s per unit on CPU, recorded as the `patchscope` cost stage. Wiki and site experiment pages show a table of unit and control text by prompt, layer and scale. Heads are not read, since they write a subspace rather than one direction. Reported, not gated. The protocol version is unchanged.
- **`openinterp patchscope-baseline`: the Patchscope readout as a blind proposer baseline.** It turns each unit's readout into one explanation by a rule fixed before scoring. The rule takes the few-shot category reading at the lowest layer read, at ×2 the replaced norm, and writes `Fires on tokens related to "<reading>".` as the explanation. That explanation is scored on exactly the held-out windows the agent's explanation was scored on. Records store those windows with their labels, so the comparison is paired and nothing is re-measured. Re-deriving all 99 archived records' scores from their own stored answers reproduces them exactly.
  - *Steps.* A first run reads every unit (cached under `--work-dir`) and writes judge prompts for the experiments whose agent explanation the `--judge-model` judged. A second run, after `explanation-judge` subagents answer, scores everything into `docs/analyses/patchscope-baseline.{md,jsonl}`. The 9 poles inspected while choosing the prompts are reported apart as a dev set.

On the 44 held-out experiments judged by Claude Haiku 5.5, the baseline scored at chance (detection 0.51, fuzzing 0.52) against the agent's 0.60 and 0.62. It matched or beat the agent on 20% of experiments for detection (sign test p = 1e-8) and 30% for fuzzing (p = 2e-4). Embedding AUROC, over all 89 held-out experiments, was 0.53 against 0.55 (p = 0.24).
  - *Why.* The readings are mostly generic categories: 38 distinct over 99 experiments, led by *country*, *noun* and *animal*.

## [0.0.5] - 2026-10-20

Ships with protocol version **0.6**.

### Added

- **Protocol 0.6: attention heads can be audited.** `openinterp audit --model M --layer L --head H` scans one head (`--unit head --random` samples one uniformly), and `score`, `review`, `reevaluate`, `reproduce` and `next` take head submissions like neuron ones. Submissions and scan evidence take any `ComponentIdentifier`, and a head's carries a `HeadProfile`. A head's strength at a token is `|W_O (z − z̄)|`, the distance between its write to the residual stream and its mean write z̄ over the scan. The record stores z̄, so every later measurement shares the zero point. The raw write norm doesn't work. On GPT-2 small L5H1 the median token sits at a quarter of the maximum, so half of all text would be "active". Against z̄, the five known GPT-2 small induction heads are active on every second-half token of repeated random tokens and almost no first-half token. A head is ablated by setting z to z̄ (mean ablation). Its causal metrics rank it against the other heads of its layer, matched on the change in each head's write. The scan also records the tokens each top example's peak attends to. It records the head's previous-token, duplicate-token and induction scores too (Olsson et al., 2022). Heads get no vocabulary lens or partner search. Head commands load the model with eager attention. Head pages live at `models/<model>/L<layer>/H<idx>.html` and in `wiki/experiments/<model>/L<layer>/H<idx>/`. Parquet gains `kind`, `head_idx`, `model_n_heads` and the three pattern scores (`neuron_idx` and `pole` are null for heads), and the home page counts heads studied. The decision rule for neuron poles is unchanged, but every existing verdict was judged under 0.5, so `openinterp next` now proposes re-evaluating them. A positive-control dry run on GPT-2 small L5H1 scanned 235,650 tokens in about 2 minutes on CPU (induction score 0.89). The proposer identified it as an induction head unprompted. It was NEEDS_REVISION after two rounds, on specificity alone (see TODO).
- **Explanation scores on held-out text** (Delphi, Paulo et al., 2025), reported, not gated. `openinterp score` cuts the corpus snippets the proposer never saw (everything but the scan's top examples) into 32-token windows. It measures each window on its own, as the judge reads it, and draws active windows evenly from 5 activation bins, plus inactive ones. Three scores:
  - *detection:* a judge given only the explanation picks the windows that activate the pole.
  - *fuzzing:* the judge decides whether the marked tokens in a window are the ones that activate it.
  - *embedding:* the AUROC of explanation–window cosine from a local sentence encoder (`sentence-transformers/all-MiniLM-L6-v2`), with no LLM.

  The judge is a LiteLLM model, or two-step: `--emit-task` writes the windows and two prompts (no activations), and `--task` scores the answers. The new `explanation-judge` subagent answers in Claude Code. **Every review records them.** `review --probes` requires `--explanation-scores`, and a one-step `review` scores the explanation itself on `--corpus`, with `--judge-model` defaulting to the reviewer. `reevaluate` stays LLM-free, so `--explanation-scores` is optional there. When no held-out window is active, detection scores false positives only and fuzzing is skipped, so scoring never blocks a review. Both commands record them as `VerificationVerdict.explanation_scores` (`ExplanationScores`, optional, so older records validate). `openinterp reproduce` re-measures the windows and re-derives the scores from the stored answers, warning on differences. Experiment pages gain an *Explanation scores on held-out text* section. It has tiles for the three scores, detection recall per activation bin, and the judged windows as token heatmaps. The explanation's misses and false alarms first and fuzzing marks dashed. `make sample-run` includes synthetic scores. Parquet gains `detection_score`, `fuzzing_score` and `embedding_auroc`. Scoring takes about 2 minutes on CPU for Qwen2.5-0.5B. On L1/N12− (VERIFIED, a bigram detector), only 69 of 4000 held-out windows were active, and a literal reading of the explanation found none of them. Its held-out activity is mostly ` in` after verbs other than *look*, which top examples alone don't show.
- **Windowed scans:** `openinterp audit --window-tokens N [--stride S]` scans each document as overlapping N-token windows that start every S tokens (default N/2), instead of whole. Long documents are read in full, and the scan's top examples become windows rather than whole documents. Each token counts once in the histogram, confound profile and partner search. It counts in the first window, or else in the fresh tail of the first later window that reaches it. So it has at least N − S tokens of context. Top examples never overlap, and they are decoded back to text, so `reproduce` re-measures them exactly as the scan did. On Qwen2.5-0.5B, a 256/128 scan counts exactly the tokens a whole-document scan does. Provenance records `snippet_tokens` and the new `snippet_stride`, and experiment pages show them. The vocabulary lens then reads each of the first 100 documents' first window. `openinterp score` now holds out every document that contains a top example, not only exact matches. Whole documents stay the default, so existing scans are unchanged.
- **Experiment costs**, reported, never gated. Every record stores what its experiment cost in `submission.provenance.costs` (`ExperimentCosts`, optional, so older records validate). That is wall time per stage (`model_load`, `scan`, `lenses`, `proposer`, `counterfactuals`, `heldout_windows`, `judge`, `embedding`, `remeasure`, `reviewer`, `probe_measurement`, `gates`, `causal_metrics`). It also records, per LLM call, the model, attempts, prompt characters, prompt/completion/cached tokens and cost from LiteLLM. The cost is read through an instructor response hook and summed over retries. The two-step flow carries costs through its files: evidence → submission, score task → scores → record. A prompt answered from a file is timed from the prompt's mtime to the answer's, with no token counts. Re-reviewing a record or re-evaluating it records only the new run's costs. Experiment pages show a *Run cost* line. With `OPENINTERP_COSTS_LOG=<file>` set, every `openinterp` command (including `check`, `wiki` and `build`) appends its wall time, stages and LLM calls to that JSON-lines ledger, and the new `openinterp costs <ledger…> [--session <file>]` summarises ledgers and `claude -p --output-format json` results. `scripts/experiment-loop.sh` now runs sessions with `--output-format json`, keeps a ledger per experiment in `logs/loop/`, and prints each experiment's cost and a running total. Tests clear `OPENINTERP_COSTS_LOG`, so `make test` inside a loop session doesn't add to it. `make test` and `make lint` are not timed separately. They fall under the session's wall time.
- **Probe results chart** on experiment pages, above the adversarial review table. Every hard negative and positive holdout is a dot on one pole-strength axis, with the reviewer's threshold (`activation_threshold` × max activation) drawn as a line. The active side is shaded. Passed probes are green dots and failed ones red crosses, so pass/fail never relies on colour alone. Dots at the same value are dodged vertically rather than hidden, and hovering one shows its strength and prompt. The axis extends past the scan max when a probe exceeds it. It is static SVG rendered at build time, like the histogram. The values stay in the table below. Records without a recorded policy or max activation show the table only.
- **`c4` corpus preset:** `openinterp corpus --dataset c4` samples the English validation split of [C4](https://huggingface.co/datasets/allenai/c4) (`allenai/c4`), the web baseline much of the SAE literature uses. C4's main branch is gzipped JSON, so the preset reads the Hub's Parquet conversion (`refs/convert/parquet`, `en/partial-validation`). Presets can now name a default `revision`, and `--revision` still overrides it. That branch has no dataset card, so when the pinned revision has none, the licence comes from the default branch's card (ODC-By here). 500 documents take about 40 seconds, and rebuilding at the recorded commit gives a byte-identical corpus.
- **`land-experiment` skill:** `choose-next-experiment` plus building the site, waiting for CI to go green and merging the PR. It merges only when every check passed on the current head and the PR touches nothing outside `wiki/`. The agent's `gh` account also needs write access. Otherwise it comments on the PR and moves on to the next experiment.

### Changed

- **`make sample-run` builds from real records.** It imports six experiments from `wiki/experiments/` (VERIFIED, NEEDS_REVISION and REJECTED, a neuron with two experiments, and two with held-out explanation scores) instead of generating synthetic ones. `examples/make_sample_audits.py` and the `examples/audits/` fixtures are gone.
- **Generated wiki indexes are no longer committed.** `wiki/README.md` and each neuron's `README.md` are gitignored and rebuilt locally by `openinterp wiki` (and by `verify`, `review` and `reevaluate`). Every experiment PR used to edit the same index rows, so parallel PRs conflicted. `openinterp check` no longer compares indexes and instead rejects a PR that commits one.
- **`scripts/experiment-loop.sh` lands experiments:** each session follows `land-experiment`, and may also run `gh run` and `gh repo view`. Its result line gains `merged` or `open`.

## [0.0.4] - 2026-10-19

Ships with protocol version **0.5**.

### Changed

- **Deploy on every push to `main`.** The site went stale because the deploy relied on an hourly cron, and GitHub's scheduled workflows are best-effort. On 2026-10-19 it fired once in about 7 hours. Every scheduled and manual run did deploy, so the `R2_BUCKET` guard was not the cause. The schedule stays as a 6-hourly backstop.
- **`openinterp next` explores twice as often:** the default `--epsilon` goes from 0.35 to 0.7. So 70% of draws audit a new random neuron rather than following up on one already studied. `scripts/experiment-loop.sh` uses the same default.
- **Token heatmaps** on experiment pages, Neuroscope-style. Each top example shows 30 tokens before and 10 after its peak, with the full snippet expandable. The peak token is underlined and bold, and hovering a token shows its exact stored strength. Before, the value was rebuilt from a capped, rounded shade. A colour legend runs from 0 to the neuron's max, and each example has a values table for keyboard and screen-reader users. Newline tokens show as `↵` so they can be shaded. The tint is capped at 80%, so token text keeps at least 4.5:1 contrast in light and dark mode. The uncapped orange fell to 3.25:1 in dark mode.

- **Protocol 0.5: causal metrics that can see a single neuron.** Sufficiency and necessity are now scored at the position where the pole's strength differs most between a minimal pair's prompts. The target is the claimed upcoming tokens for lookahead claims and next-token KL otherwise. Each score is the median percentile of the pole's effect among the 32 same-layer neurons (`ReviewPolicy.causal_null_neurons`) whose strength changes as much between the pair. Control pairs are skipped. Before, the score was the fraction of the top-1-logit gap restored, which read ≈ 0 for every neuron. On the four Qwen2.5-0.5B neuron poles in the registry the new scores range from about 0.6 (L11/N4255+) to 1.0 (L23/N726−). Still recorded, not gated. `CausalMetrics` gains `target`, `target_tokens`, `sufficiency_effect`, `necessity_effect`, `null_neurons` and `pairs_scored`. All are optional, so older records still validate. Parquet gains `causal_target`.

### Added

- `openinterp corpus`: samples a scan corpus from a Hugging Face Parquet dataset without downloading all of it, by reading seeded random row groups over HTTP. Presets: `fineweb-edu` (`HuggingFaceFW/fineweb-edu`, sample-10BT, the default) and `pile-10k`, or any dataset with `--files`. It writes `corpus.jsonl` and a `corpus.source.json` sidecar (`CorpusSource`: dataset, commit, files, seed, sizes, licence, SHA-256). Audits record the source in `provenance.corpus_source` when the corpus still matches it, and experiment pages show the licence. The same seed and revision rebuild a byte-identical corpus. Replaces the README's Pile snippet.
- **Attention heads, step 1: identifiers and hooks.** `ComponentIdentifier` is a union of `NeuronIdentifier` (`kind = "mlp_neuron_pole"`, the default, so existing records validate unchanged) and the new `HeadIdentifier` (`kind = "attn_head"`, `head_idx`, slug `L<layer>/H<idx>`). `NeuronHookRunner` resolves each layer's attention output projection (Llama/Qwen/Mistral/Gemma/Phi, GPT-2, GPT-NeoX, GPT-J, OPT, Falcon) and gains `head_outputs`, `head_write_norm`, `head_output_weights`, `attention_patterns` and `hooks(head_interventions=…)`, plus `ablate_head`. `_load_runner` takes `attn_implementation` (patterns need `"eager"`). Submissions still accept neuron poles only and reject a head with a clear message, so the decision rule and `PROTOCOL_VERSION` are unchanged.
- **Most recent experiments** on the home page. It shows the latest 10 experiments, whatever their verdict, newest first. Each row has review time (UTC), neuron, status, evidence strength, hypothesis, proposer and reviewer, and a tag for re-measurements. On small screens the date moves under the neuron.
- **Proposer and reviewer as Claude Code subagents, with no API key.** `.claude/agents/neuron-proposer.md` and `neuron-reviewer.md` answer prompt files. The reviewer has no tool that runs the model, so it can't see probe activations before its probe set is final.
- Two-step CLI commands that write a prompt and exit, then take the answer as JSON, so no process waits on an answer file. They are `openinterp audit --evidence-out` (scan evidence as `ScanEvidence` JSON plus the proposer's prompt), `audit --evidence … --hypothesis …` (builds the submission without rescanning), `review --emit-prompt` (loads no model) and `review --probes …`. `--agent-model` is required with an answer file, so the record names the model that wrote it.
- `scripts/experiment-loop.sh`: for `external/<name>` models the driving session now uses the subagents.
- CI job **Reproduce records**: runs `openinterp reproduce --base-ref origin/<base>` on every pull request, on CPU, with Hugging Face weights cached between runs. Only models in its `ALLOWED_MODELS` are loaded (`openinterp reproduce --allow-model`). Failures appear as file annotations and in the job summary.
- Auto-signing: `verify`/`review` and `reevaluate` sign each new experiment record when the machine holds a signing key (`~/.ssh/openinterp_signing` or `$OPENINTERP_SIGNING_KEY`) that is listed in `.github/allowed_signers`. So a maintainer's own runs and experiment loops skip CI reproduction. `OPENINTERP_AUTO_SIGN=0` turns it off.
- `openinterp sign`: a maintainer vouches for experiment records with an SSH key (`ssh-keygen -Y sign`), writing `<id>.json.sig` next to each record. `reproduce` skips records signed by a key in `.github/allowed_signers`, read from the base branch under `--base-ref` so a pull request can't trust its own key. It fails on an invalid signature. `openinterp check` flags signatures whose record is missing. A signature doesn't change the verdict.
- `openinterp reproduce`: re-runs a record's scan evidence, counterfactual deltas and review against the model commit and dtype it pins. It runs under the record's own policy and with no LLM calls. It fails on any number outside tolerance (`--atol` × scale + `--rtol` × |recorded|) and on any differing pass/fail, gate or status. `--base-ref` picks every record a branch adds or changes.
- `RunEnvironment` (device, weights dtype, model commit, openinterp/torch/transformers versions) is recorded on every verdict and on the scan's provenance. The model commit is now resolved from the Hugging Face cache, because `config._commit_hash` is empty in recent transformers. Five of the seven records in the registry have no `model_revision`. `_load_runner` takes a `revision`.
- `ActivationPatcher.patch_many`: patch many neurons of one layer, one per batch row, with any effect function (`metric_change`, `next_token_kl`). `logit_direction_metric` scores logits along a centred vocabulary direction.

## [0.0.2] - 2026-10-18

Ships with protocol version **0.3**.

### Added

- README "Get started" guide for contributors. It covers setup, API keys for an independent proposer and reviewer, and building a Pile scan corpus. It also covers running an experiment with Claude Code or by hand, and claiming and posting it as a PR. `submissions/` and `corpus.jsonl` are now git-ignored.
- **Protocol v0.3: covariance and confounds.**
  - Near-duplicate probes cluster into single observations (`core/stats.py`). The probe-count gates, balanced accuracy and significance use these effective counts.
  - The scan (`harness/scan.py`) gathers in one pass the top examples, the most correlated same-layer neurons (`harness/covariance.py`) and a confound profile. The profile holds token-identity and position R², frequency correlation and trigger tokens (`harness/confounds.py`).
  - New gate `beats_confound_baseline`: the hypothesis must match or beat token-identity, position and never-active baselines on the reviewer's probes.
  - Joint ablation of the pole with its correlated partners, reporting a redundancy ratio (recorded, not gated).
  - Re-measurements of an earlier probe set are marked as not independent, rank after the original, and are excluded from the most-conclusive list.
  - The home page estimates expected false discoveries among VERIFIED claims.
  - Neuron pages summarise both poles together.
  - The proposer sees the confound profile and correlated neurons.
- **Jacobian lens** (`harness/jlens.py`, Gurnee et al., 2026, arXiv:2607.15495).
  - Reads each pole's output direction through both the context-averaged Jacobian lens and the logit lens, and records `submission.vocabulary_lens` (both token lists, overlap, cos(w, J·w), kurtosis).
  - Estimates J·w from one perturbed forward pass per prompt and sign. Tests check it against exact autograd on Llama-style and GPT-2 models.
  - On Qwen2.5-0.5B the two lenses share 0/10 tokens up to the middle layers and converge only near the output.
  - Shown on the site and wiki, exported to Parquet, fed to the proposer. The vocabulary skill now defaults to it.
- **Rank-based and regime-aware correlation.**
  - Frequency correlation is Spearman's ρ (tie-aware, exact).
  - Partner neurons are found per *pole* by co-activation lift (`PartnerSearch`). It uses a fixed-seed reservoir sample plus the target's top tokens, with chunked Spearman and Pearson kept for reference.
  - Partners are ranked and selected by the 95% Wilson lower bound of the lift, which the new `min_partner_lift` and `min_partner_coactive` policy fields govern.
  - Global Pearson missed real partners: on L11/N4255 every |r| was below 0.07, while co-activation lift was at least 10.
- Every experiment is published, null and superseded results included. The site follows Model → Layer → Neuron → Experiments, with model and layer index pages, and each neuron page lists all experiments on both poles.
- Experiments are ranked by *conclusiveness*: the posterior probability that balanced accuracy exceeds 0.6, folded to |2P − 1|, so strong evidence ranks high in either direction (`builder/significance.py`). The home page features the most conclusive results in both directions.
- A write-once experiment archive: `wiki/experiments/**/<id>.json` stores each experiment's full record next to its page. `openinterp check` validates it and rejects edits to it.

### Changed

- `openinterp build` reads the wiki archive (`--wiki-dir`) instead of `audits/`, and `--include-unverified` is gone because everything is published.
- `registry.parquet` has one row per experiment, with `experiment_id`, `is_latest`, `p_useful`, `conclusiveness` and `evidence_direction`.
- Neuron pages moved from `neurons/<slug>.html` to `models/<model>/L<layer>/N<idx>.html`.

## [0.0.1] - 2026-10-18

First release. Ships with protocol version **0.2**.

### Added

#### Harness and protocol

- Strict Pydantic v2 schemas for neuron identifiers, counterfactual pairs, lookahead profiles, causal metrics, submissions, verdicts and audit records.
- `NeuronHookRunner`: hooks on MLP down-projection inputs for Llama/Qwen/Mistral/Gemma, GPT-2, GPT-NeoX, GPT-J, OPT and Phi, with positive/negative pole isolation and corpus scanning.
- Activation patching: denoising, noising and resample ablation per pole, with optional freezing of downstream MLP outputs to mitigate self-repair.
- Attribution patching for whole layers in one backward pass.
- Lookahead profiling (pole-ablation KL and concentration) and vocabulary projection of neuron output directions.
- `ProposerAgent` and `ReviewerAgent` using LiteLLM and instructor (default model `anthropic/claude-opus-5-5`). Verdicts are computed deterministically by `evaluate_submission`.
- Protocol v0.2 (`docs/PROTOCOL.md`). It is a gated decision rule using balanced accuracy over hard negatives and positive holdouts. It adds a counterfactual tolerance relative to the prediction, minimum probe counts and an independent-review gate. It replaced v0.1's weighted mean and absolute Δ tolerance of 0.35 before release, after v0.1 verified an over-broad hypothesis.
- Experiment provenance on submissions (model revision, corpus hash, selection method, seed) and the review policy stored on verdicts.
- CLI commands `audit` (including `--random --seed`), `verify`/`review` (which also accepts an existing audit record), `reevaluate`, `build`, `deploy`, `wiki`, `check` and `next`.

#### Registry, wiki and site

- Experiment wiki (`wiki/`): a write-once Markdown page per completed experiment, with per-neuron history pages and a home index. `verify` and `reevaluate` write pages automatically, `reevaluate` saves the superseded verdict before overwriting a record, and `openinterp wiki` backfills existing records.
- `openinterp next` and the `choose-next-experiment` skill: a randomised next-experiment planner (ε-greedy exploration of random neurons, Boltzmann sampling over follow-ups, decay for repeats, recency and open-PR claims). It prints a seed for reproducibility.
- Static site builder (Jinja2 + Tailwind) with per-layer coverage, leaderboards, Pagefind search and a DuckDB-Wasm SQL console. The registry is exported as `registry.parquet` plus content-addressed snapshots.
- The build is deterministic. There are no build timestamps, orderings are total, and stale pages are removed, so unchanged records rebuild byte-for-byte.
- Cloudflare R2 delta sync with per-file cache policies:
  - content-addressed files upload first and HTML last.
  - `pagefind/` only syncs when a source file changed.
  - `data/snapshots/` is never deleted.
  - an optional Cloudflare cache purge covers only the changed URLs.

#### Project infrastructure

- GitHub Actions CI: lint, a 500-line limit on source and documentation files, tests, and `openinterp check` (audit/wiki pairing, stale indexes and write-once pages) on every PR.
- Hourly deploy workflow that rebuilds from `main` and delta-syncs to R2. It is skipped until the `R2_BUCKET` variable is set.
- A PR template with an experiment checklist.
- Ten Claude Code research skills in `.claude/skills/`, each grounded in the interpretability literature.
