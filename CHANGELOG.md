# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/).

The project has two version numbers:

- **Package version** (`openinterp.__version__`): the code. Bump it in `openinterp/__init__.py`, which `pyproject.toml` reads.
- **Protocol version** (`openinterp.core.schemas.PROTOCOL_VERSION`): the review decision rule. It is stored in every verdict and documented in `docs/PROTOCOL.md` §6. A protocol change always needs a package release too, but not the other way round.

## [Unreleased]

### Changed

- **One definition each for values the sweep found retyped.** The active line (`ACTIVATION_THRESHOLD` in `core/schemas.py`, previously `0.25` in `cli_scan.py`, `show.py` and `harness/probing.py`); the evidence strength bands (`STRONG_EVIDENCE`, `evidence_strength` in `builder/significance.py`, previously also in `_macros.html` and the registry SQL); and the unit statuses with their colours (new `builder/statuses.py`, previously also the keys of `map_fill` and `status_badge` in `_macros.html`). No output changes.
- **The wiki directory's default and layout are defined once** (`openinterp/core/paths.py`: `DEFAULT_WIKI_DIR`, `experiments_dir`, `draws_dir`), and every command's `--wiki-dir` comes from `wiki_dir_option()` in `cli.py`. Previously `Path("wiki")` was retyped in 14 options and defaults and `wiki_dir / "experiments"` joined by hand in seven places. `--wiki-dir` now rejects a file everywhere, as most commands already did. A test in `tests/test_single_source.py` keeps the joins from coming back.
- **Numbers the README, skills and agent files quote from code are pinned by tests** (`tests/test_single_source.py`): the scan cache cap and sample size, the line limit, the 10–20 probe bounds (`ProbeSet`), GPT-2's window, ε, the active line and the planner's base weights. ε's default is now defined once (`DEFAULT_EPSILON` in `planner.py`, previously also typed in `openinterp next --epsilon`). The site templates' numbers turned out to be maths or protocol history, which can't drift, or display thresholds typed only once.

## [0.0.11] - 2026-10-31

Ships with protocol version **0.8**.

### Added

- **Labelled concept sets from annotated datasets** (`openinterp concepts`, `openinterp/concepts.py`, `core.probing.ConceptSource`; TODO, Datasets). It writes the `{"text": ..., "spans": [[start, end], ...]}` JSON lines that `openinterp probe-compare --train/--test` reads, from human annotations instead of a regular expression, for `sparse-probing-search` and reviewers' positive holdouts. Presets: `conll2003-ner` (PER, ORG, LOC, MISC) and `conll2003-pos` (Penn Treebank tags), `ud-upos` and `ud-deprel` (any Universal Dependencies treebank via `--subset`, default `en_ewt`), `language-identification` (`papluca/language-identification`, 20 languages) and `ag_news` (four topics). Word tags give a span per tagged word, matching the label with or without a BIO prefix or subtype (`B-PER`, `nmod:poss`). CoNLL's pre-tokenised words are joined as written ("(AP) Smith doesn't"). UD words are located in each sentence's text, and a multiword token's words share its surface form (French "du" is DET and ADP). Sentences are joined into documents of up to `--max-chars`, by UD's `newdoc`/`newpar` where it has them. Document classes span the whole text, with half the sampled documents of the class. Without `--label` it lists the split's labels and counts. The `<name>.source.json` sidecar pins the dataset commit, split files, column, label, seed and licence, which for UD is the treebank's (en_gum is CC BY-NC-SA). CoNLL-2003 is Reuters text and ag_news's licence is unknown, so neither should be quoted in the wiki.
- **Cross-reference with published dictionaries** (`openinterp crossref`, `openinterp/crossref.py`, `harness/crossref.py`; TODO, Scope expansion). For each neuron pole whose model has a dictionary preset at its layer, it finds the 5 latents whose decoder best aligns with the pole's write and, for transcoders, the 5 whose encoder best aligns with the neuron's read. Cosines are taken in residual coordinates with norms folded in, and oriented, since a latent fires only non-negatively. Each side also records chance (what a random direction's best match reaches) and how the pole ranks among its layer's neurons. Rows go to `docs/analyses/dictionary-alignment.jsonl`, with dictionary and latent index only, never descriptions. Neuron pages list them, linked to the latent's page here or on Neuronpedia. `openinterp aligned-latents <slug>` prints them with descriptions fetched live, and `openinterp review --dictionary-latents` (off by default) shows the reviewer the above-chance ones that have a description. `DictionarySpec.neuronpedia` names the Neuronpedia source where it was checked to index the same latents: GPT-2's `tres-dc` (24 latents across layers 2–11 peak on the same tokens), Gemma Scope's canonical MLP and residual SAEs, and Llama Scope's residual SAEs. Reported, not gated. First run, over all 1,051 archived poles, comparing each pole's latest verdict: on GPT-2, VERIFIED poles' best write match has median cosine 0.77 (64% above 0.5), against 0.34 for NEEDS_REVISION and 0.27 for REJECTED. On Qwen2.5-0.5B's own transcoders the gap is small (0.26 against 0.21).
- **An agents page** (`agents/index.html`, `openinterp/builder/agents.py`; TODO, Site). One row per agent model and role (proposer, reviewer, judge): experiments, the VERIFIED rate with its sample size, self-reviewed experiments counted apart from the rate, and costs (priced share, mean, per VERIFIED). Each model has its own page (`agents/<slug>.html`) with the same by role, total cost, and its 20 most recent experiments. Agent names on experiment, neuron and home pages link to these pages, and the header links the agents page. It replaces the home page's "Submitting agents" and "Agent costs" sections, which are now one line with a link. Names are shown as recorded; the name cleanup (TODO, Housekeeping) will merge spellings of one model.
- **`openinterp next` rescans records scanned on the built-in sample** (TODO, Pipeline). Before `audit` defaulted to `corpus.jsonl` (f3aeb00a), 572 records were scanned on the 552-token built-in sample, the latest experiment on 475 units among them, so their max activation, the denominator of every "active" line, means little. `reevaluate`, `independent_review` and `replicate` draws on them inherited that scan. The planner now offers a `rescan` draw for these units instead of any review kind (weight 2.0, as `revise`): a new audit on `corpus.jsonl` that supersedes the record, then verify. `opposite_pole` draws are still offered. The site badges such experiments and poles "built-in sample". `AuditRecord.scanned_on_builtin_sample` and `core.schemas.BUILTIN_CORPUS` name the condition.
- **Driver-model pilots** (`docs/analyses/driver-model-pilot.md`). Sonnet and Haiku drove real experiments through `scripts/experiment-loop.sh`: 4 with Sonnet, then 4 + 8 with Haiku. Every one landed. Haiku's driver cost $0.02–0.08 per experiment against Sonnet's $0.41, including Qwen explores and a scan stopped on a default-on unit. Haiku needed one rescue: a stopped draw's PR left as a draft.
- **Fewer tokens for the driving session** (TODO, Performance).
  - *`openinterp next --steps`* (`openinterp/draw_steps.py`) prints every step of the draw as exact commands: claim, read the history, scan, the proposer, reviewer and judge subagents (or `--proposer`/`--reviewer` API models) with their `usage` calls, then post. The key, branch, `exchange/<key>/` paths and `--corpus` are filled in. An explore draw's unit is worked out from its seed and the model's cached `config.json`, mirroring `pick_unit`'s draws, so it can be claimed before the scan starts. `choose-next-experiment` and `scripts/experiment-loop.sh` use it. Planner candidates carry the record they follow up (`record`) and their `audit` options.
  - *`openinterp show <record | submission | ev.json | unit directory>`* (`openinterp/show.py`) summarises without the JSON: verdict, failed gates and probes, scores and each page's Discussion, or a scan's corpus, peak, top examples and lenses. A 300 KB record and its 25 KB page come to about 25 lines. `--full` doesn't cut anything. The skill and the `neuron-proposer` agent read history with it.
  - *Terser output.* Progress bars are off when stderr isn't a terminal, torch's macOS redirect note is gone, and models load with `dtype=` (transformers deprecated `torch_dtype=`). `openinterp --quiet` also turns off progress bars on a terminal and library warnings.
- **Per-token labels for the scan, and the confound they give** (`harness/annotations.py`, `ConfoundProfile.labels`). A tagger labels character spans of a document, the scan aligns them to the model's tokens through the tokenizer's offsets, and each label set gets a variance explained (`r2`, like `token_r2`) and a binned, Miller–Madow-corrected mutual information in bits. It also records each label's count, mean strength and active tokens. The proposer sees them, and the experiment pages show them. Reported, not gated, and neuron scans only for now. The language, WordNet, syntax-tree and part-of-speech taggers in TODO plug into it.
  - *Language.* `openinterp corpus` records each document's language as `lang` when a preset (`wikipedia-multilingual`) or `--lang-pattern` says which part of a file glob names it. The sidecar records the pattern. `openinterp audit` reads it as the `language` label set, also under `--max-tokens` sampling (`corpus.sample_indices`). A `wikipedia-multilingual` corpus built now differs byte for byte from one built before, since its lines carry `lang`. Corpora without the field read and scan as before.
  - The confound schemas (`ConfoundProfile`, `TokenStat`) move to `core/confounds.py` and are still importable from `core/schemas.py`.
- **Null calibration of the review** (`docs/analyses/null-calibration.md`). It measures the protocol's false-positive rate on claims that should fail.
  - *Shuffled labels* (`scripts/null_calibration.py shuffle`, no LLM calls): each record's hard-negative and holdout labels are permuted among its measured probes, and the stored activations are re-decided. Over 1,151 native records, 2% of permutations are VERIFIED, and 4% on the probe sets of VERIFIED records. 20-probe sets give 0.5%, against 2.1% for 16-probe sets.
  - *Swapped unit* (`null_calibration.py swap`): each VERIFIED pole's hypothesis and probes are reviewed against a random neuron of the same layer and pole, scanned as its own audit would scan it. 0 of 255 are VERIFIED, all stopped by `counterfactual_reproduction`; without the proposer's gates, 5 of 255 (2%) pass. With fresh reviewer probes written from the swapped neuron's own scan (`scripts/swap_fresh.py`, 40 swaps), 0 of 40 pass even without the proposer's gates.
  - *Rotated basis* (`scripts/basis_null.py`): random directions in Qwen2.5-0.5B's MLP hidden space are audited by the full pipeline, against native positive poles run through the same code with the same agents, blind to which is which. Native: 18 of 30 VERIFIED; rotated: 1 of 30 (paired sign test p = 1.5 × 10⁻⁵). Rotated units fail on specificity.
- **A `basis` dictionary kind and an `mlp_hidden` input site** (`DictionaryProfile`, `harness/sites.py`): a latent reads the MLP's hidden activations (the down projection's input) along one direction and writes through the down projection. With the identity basis, its latents are exactly the native positive poles. Used by the rotated-basis null; weight wiring doesn't read it yet.
- **A 40-line limit on functions**, checked by `scripts/check_line_limit.py` in `make lint` and CI beside the 500-line file limit. A function is measured as its signature (one line, however it wraps) plus its body, leaving out decorators and the parameter list (so long Click option lists don't count) and the docstring; tests are exempt. Mark the rare function that reads better whole with `# long-function: <reason>` on its `def` line; this is not a `# noqa`, because ruff warns on codes it doesn't know.

### Changed

- **`scripts/experiment-loop.sh` drives sessions with Haiku by default** (`--driver claude-haiku-5-5`; pass `--driver ''` for claude's own model). Proposer, reviewer and judges are subagents with their own models, so this changes only the cost of driving: $0.02–0.08 per experiment, against $0.41 for Sonnet. `revise`/`new_hypothesis` draws and failing CI checks didn't come up in the pilots, so check the first unattended runs for them.
- **`openinterp next --steps` says to land a stopped scan's PR**, which holds the draw record. Before, it said to "post it", and a Haiku driver left one as a draft. **`experiment-loop.sh` runs `uv sync` before each session**, so a fresh venv's build output no longer buries the first `openinterp next`.
- **`land-experiment` merges in two commands.** It reads the head SHA, then passes it to `gh pr merge --match-head-commit`, instead of `SHA=$(…)`, which Claude Code's permission check refused in every pilot session.
- **`openinterp audit` no longer falls back to the built-in sample corpus.** Without `--corpus` it scans `./corpus.jsonl`, the registry's scan corpus, and says so; if that file isn't there it stops and says how to build it. The ~552-token built-in sample made scans that said little and was easy to run by mistake. Other commands (`scan`, `score`, `review`) are unchanged.
- **The reviewer writes 20 probes by default** (`openinterp review --n-probes`, was 16), the protocol's maximum. In the null calibration, 20-probe sets verified under shuffled labels a quarter as often as 16-probe sets. No gate or threshold changes, so the protocol version is unchanged.
- **The 45 functions over 40 lines are split**, so none needs the exemption. The longest were `audit` (`cli_evidence.py`, 154 lines), `scan_evidence` (`evidence.py`, 147), `main` (`scripts/train_transcoders.py`, 106) and `evaluate_submission` (`agents/reviewer.py`, 104). Behaviour is unchanged: the built site is byte-identical, and scans, submissions, reviews, reproductions, score tasks, plans, `activations` output and the Patchscope baseline report match the code before the split. Along the way, `scan_evidence` takes a `ScanRequest` instead of 17 parameters, and new modules hold what moved out of files near the 500-line limit: `cli_submission.py` (the steps of `audit` after the proposer answers), `agents/review_measurements.py` (what the reviewer measures) and `builder/registry_stats.py` (the home page's queries).

## [0.0.10] - 2026-10-30

Ships with protocol version **0.8**.

### Added

- **`wikipedia-multilingual` corpus preset** (`wikimedia/wikipedia`, the November 2023 dump), for language-identity and script neurons. `openinterp corpus --dataset wikipedia-multilingual` takes an equal share of articles from ten languages in eight scripts: English, German and French (Latin), Russian (Cyrillic), Greek, Arabic, Hindi (Devanagari), Chinese (Han), Japanese (kana and kanji) and Korean (Hangul). To make this possible, `--files` (and a preset's `files`) can now hold several comma-separated globs, and each glob gives an equal share of the documents in the order given, the first taking any remainder. Each language's articles are sampled as before, and the source sidecar records the globs. Row groups hold 1,000 articles (10–22 MB), so the preset takes 50 documents per row group: 500 documents read one row group per language and take about 20 seconds. They come to about 347,000 Qwen2.5 tokens (median 584 per document, cut at 3,000 characters; 20,600 for Korean to 59,600 for Greek) and 588,000 GPT-2 tokens. Rebuilding at the recorded commit gives a byte-identical corpus. Licence: CC BY-SA 3.0 and GFDL, so excerpts in the wiki need attribution and the same licence. `uonlp/CulturaX` was passed over because it is gated.
- **A dictionary for Qwen2.5-0.5B**, the registry's default model, which no public dictionary covers: `qwen2.5-0.5b-transcoders`, skip transcoders for all 24 layers (16,384 latents each), hosted at [`sackfield/qwen2.5-0.5b-transcoders`](https://huggingface.co/sackfield/qwen2.5-0.5b-transcoders). Scan with `--window-tokens 1024`.
  - **Training.** `scripts/train_transcoders.py` trains top-k (k = 32) skip transcoders with AuxK and exports them as JumpReLU with one global threshold per layer. The data is 13.5M tokens of `NeelNanda/pile-10k`, one pass, leaving out the documents the scan corpus draws from.
  - **Fit** on the scan corpus, at `mlp_in` (after the MLP norm and its gain), through position 1024 and leaving out the first token: 59–93% of the MLP output, with L0 about 32 and at most 0.6% of latents dead. Without the skip path, at most 34%.
  - **`hf_models/`** holds the Hub repository's card, metadata and training log; the weights are ignored by git.
- **Llama Scope presets for Llama-3.1-8B** (He et al., 2024; the 8x, 32k-latent dictionaries): `llama-scope-8b-res-saes`, `llama-scope-8b-mlp-saes` and `llama-scope-8b-transcoders`. Scan them with `--dtype bfloat16`; in float32 the model takes 32 GB.
  - **Format.** OpenMOSS `lm_sae` checkpoints (`encoder.weight` …, with `hyperparams.json` beside `checkpoints/`) now load. The dataset-norm input and output scaling and the single JumpReLU threshold are folded into the weights. The record still pins only the repository, revision and file, and the hyperparameters live at that same revision.
  - **Read as Neuronpedia reads them.** A latent is active where its pre-activation exceeds θ × the input scale (SAELens's convention), at strength pre × ‖W_dec[f]‖ ÷ input scale.
    - On one sentence, two layer-15 residual latents fire on the same tokens with the same values as Neuronpedia's `15-llamascope-res-32k`, to bf16 precision.
    - That reading fits about 4 points worse than the raw threshold (residual 62.8% against 66.5% at layer 15), with L0 33 instead of 228.
    - The scales match the corpus: the mean `resid_post` norm is 10.80 against 10.81 recorded.
  - **Fits** at layers 0, 8, 15, 24 and 31, through position 1024, leaving out the first token:
    - Residual SAEs: 54–86%.
    - MLP-output SAEs: 30–84%, weakest in the middle layers.
    - Transcoders at `mlp_in_normalized`: 44–87%, the best of the three input sites at every layer. The others fit too (−0.2 to 0.85), mostly near the last layer.
    - Unlike Gemma Scope's, the fits fall 2–8 points from the first 256 positions to positions 512–1024.
  - **Records** for this model must be signed, like every model CI doesn't reproduce.
- **Residual-stream SAEs** (`gemma-scope-2b-res-saes`: Gemma Scope's canonical 16k SAEs for Gemma 2 2B). They introduce a new site, `resid_post`, the residual stream after the feature's layer (TransformerLens's `hook_resid_post`). The latent reads that site, writes back to it, and is ablated, steered and patched there.
  - **`DictionaryProfile.output_site`** can now be `resid_post`. It always follows from the input site: only a `resid_post` dictionary writes to the residual stream.
  - **Wiring** counts the feature's own layer's MLP neurons and heads as upstream.
  - **Prompts and pages** describe the fit against the residual stream, not the MLP output.
  - **Fit:** 76–93% of the residual stream's variance at layers 0, 5, 12, 20 and 25 (L0 65–116), flat through position 1024. Read one step earlier, before the MLP, the fit is −3 to −8.
  - **Comparing with neurons:** the learned-basis comparison sets these latents against the same layers' MLP neurons, so it changes the site as well as the basis.
- **Four more dictionary presets** in `openinterp/harness/dictionaries.py`, for the learned-basis baseline: `gemma-scope-2b-transcoders` and `gemma-scope-2b-mlp-saes` (Gemma 2 2B, JumpReLU), `llama-3.2-1b-transcoders` and `qwen3-0.6b-transcoders` (circuit-tracer). Each input site was checked by reconstruction on 16 corpus documents through position 1024, leaving out the first token. At every checked layer the chosen site was the only one with a positive fit. Gemma transcoders 54–93% of the MLP output's variance at layers 0, 5, 20 and 25 (32% at layer 12, L0 6). Gemma MLP SAEs 62–95%. Llama 69–81%. Qwen3 41–73%. No fit fell off with position.
  - **New input site `resid_mid`**: the residual stream before the MLP's norm, which the Llama transcoders read.
  - **Skip transcoders.** A `W_skip` in the file is added to the reconstruction as `x @ W_skip.T`, circuit-tracer's convention; a latent's write doesn't include it. For Llama 3.2 1B the skip carries most of the fit: the latents alone explain 9–27%.
  - **Gemma 2's post-MLP norm.** A dictionary's output, and the write that ablating a latent removes, are now what the MLP adds to the residual stream, after `post_feedforward_layernorm` where there is one (TransformerLens's `hook_mlp_out`). Against the down projection's output, Gemma Scope fits at −180 (transcoders) and −14 (SAEs). Nothing changes for models without that norm, which covers every existing record.
  - **The fit leaves out each piece's first token.** Dictionaries aren't trained on that attention sink. With it included, a Llama 3.2 1B scan reported a fit of −14,133; without it, 79%. This changes only the reported `explained_variance`, `mean_l0` and `dead_share` of new records, which reproduction doesn't compare. A latent's `density` still counts every token.
  - **Loading.** NumPy `.npz` weights load, and a preset can name a different file for each layer (Gemma Scope's L0 varies by layer).
  - **Fixed:** wiring for a dictionary that reads `mlp_in` measured the latent on the residual stream without first applying the norm. No earlier preset read that site.

- **Induction-head positive control** (GPT-2 small; records under `wiki/experiments/openai-community--gpt2/L5/H1/` and the four transfer heads). The protocol VERIFIES a known induction head given its own explanation, but no single explanation verified across the family.
  - **L5H1 took four rounds.** The two unrecorded dry-run rounds and round three (the first registry record) were NEEDS_REVISION, all on specificity only. The dry runs excluded fuzzy and template repeats, and their reviewer labelled probes by words, not tokens. Round three said a single repeated token is inactive, but a single repeated content token fires when the token before it is *similar* to the one before the earlier copy (`purple green` after `red green`).
  - **Round four VERIFIED** (confidence 0.90; hard negatives 11/11, holdouts 4/5, counterfactuals 9/9, sufficiency 0.95, necessity 1.0). Its explanation: an induction head with a fuzzy match on the preceding token. The reviewer was Haiku 5.5, whose hard negatives were easy, so this is the weaker half of the result.
  - **Stopping rule.** It was fixed before round four (two more registry rounds; reviewer-mislabel rounds don't count; fresh, alternating reviewers; the unchanged gate; pass means the explanation also transfers to the other known induction heads). Applied **unchanged**, with counterfactual pairs and expected deltas, to L5H5, L6H9, L7H2 and L7H10 (reviewer Sonnet 5.5), it was NEEDS_REVISION on all four. Counterfactual reproduction failed everywhere (2–4 of 9): the fuzzy-preceding-token behaviour is L5H1's own. L5H5 (hard negatives 4/11) and L6H9 (8/11) also match differently. L7H2 (11/11) and L7H10 (10/11) fit the probe-level description.
  - **Conclusion.** Under the rule, revising narrowed the explanation to one head; each head was then audited on its own (below).
  - **Token check.** Across the four Sonnet probe sets, the token check caught eight mislabelled hard negatives.
- **Each known GPT-2 small induction head VERIFIES with its own explanation.** L7H2 verified in round one (confidence 0.95). L5H5 (0.91), L6H9 (0.95) and L7H10 (1.00) verified in round two, after one revision each; L6H9's first round was REJECTED. Every head got a fresh Opus 5.5 proposer working only from its own scan, Sonnet 5.5 reviewers with the token check, and a budget of two revisions per head; none needed the second. Hard negatives passed 9–11 of 11, holdouts 5/5, counterfactuals all reproduced, and sufficiency and necessity were 0.91–1.0. Sonnet's hard negatives pressed closer to the line than Haiku's had (several at 0.75–0.94 of it).
  - **The heads differ.** L7H2's strength grows with the length of the matched run. L5H5 matches spelling across case and the leading space (`Mal|one` matches ` Malone`). L6H9 fires on names, identifiers, repeated lists and recurring phrases. L7H10 is strongest when it copies a piece of a rare multi-token word.
  - **Why round one failed.** Each round-one failure (specificity only) came from a proposer putting common repeats in a band that straddled the activity line. The round-two prompt asked for a plain above-or-below call, and that fixed it.
  - **Caveats.** L7H10's proposer reported that its rule still mislabels about 8 of 45 ordinary-word repeats it tried. L6H9's explanation lists ` to Paris in` as below the line although its own recurring-phrase clause would put it above. Token checks caught 23 more mislabelled hard negatives, at least two in each of the seven probe sets.

- **Probe comparison** (`openinterp probe-compare`; `docs/analyses/probe-comparison.md`, rows in `probe-comparison.jsonl`). It compares a VERIFIED neuron pole with linear probes for its concept, on tokens labelled by a regular expression that never sees the model. The probes are trained on one corpus and tested on another. They are logistic and mass-mean probes (Marks & Tegmark, 2023) on the layer's MLP hidden activations and on the residual stream after the layer, and k-sparse probes over the hidden layer's neurons (Gurnee et al., 2023). The report gives the pole's held-out balanced accuracy (fitted, and at the protocol's line), its rank among the layer's neurons, the cosine of each probe's direction with the pole's, and the neurons needed to match the dense probe. On five VERIFIED poles, trained on the Pile sample and tested on FineWeb-Edu, no Qwen2.5-0.5B pole was its layer's whole representation of its concept. Each concept decoded at AUROC ≥ 0.99 and needed about 32 neurons, against 0.68–0.87 balanced accuracy for the pole alone. L6/N4837+ (feminine reference) and L13/N3326− (years) rank 2nd and 3rd at their layers. L4/N3208+ (years) and L17/N1420+ (thousands-separated numerals) rank 725th and 152nd, partly because their labelling rules are broader than their explanations. GPT-2 L0/N1923+ (' Street') ranks 1st, but with 15 held-out positives the row is too thin to read. `scripts/probe_comparison.py` builds the labels and gathers the rows. Reported, not gated (`docs/PROTOCOL.md` §4).

- `openinterp review --check-probes <probes.json>` shows a reviewer its own probes as the model's tokens, and for an attention head the token runs each probe repeats. It writes `<name>.check.prompt.md`, loads only the tokenizer, so the reviewer still sees no activations, and is answered by rewriting the probe file. In the GPT-2 L5H1 positive control, 5 of the reviewer's first 11 hard negatives had exact 2–3-token repeats once tokenized (e.g. 'Zanzibar' → 'Z','anz','ib','ar'). The token check is now step 5 of the subagent flow in `choose-next-experiment`.

- **Records that predate their corpus's sidecar show its source.** `openinterp build --corpus-sources` (default: the committed `corpus.source.json`) matches records with no `provenance.corpus_source` to a sidecar by `corpus_sha256`. ## [0.0.5] - 2026-10-20

Ships with protocol version **0.6**.

### Added

- **Protocol 0.6: attention heads can be audited.** `openinterp audit --model M --layer L --head H` scans one head (`--unit head --random` samples one uniformly), and `score`, `review`, `reevaluate`, `reproduce` and `next` take head submissions like neuron ones. Submissions and scan evidence take any `ComponentIdentifier`; a head's carries a `HeadProfile`. A head's strength at a token is `|W_O (z − z̄)|`, the distance between its write to the residual stream and its mean write z̄ over the scan, which the record stores so every later measurement shares the zero point. The raw write norm doesn't work: on GPT-2 small L5H1 the median token sits at a quarter of the maximum, so half of all text would be "active". Against z̄, the five known GPT-2 small induction heads are active on every second-half token of repeated random tokens and almost no first-half token. A head is ablated by setting z to z̄ (mean ablation), and its causal metrics rank it against the other heads of its layer, matched on the change in each head's write. The scan also records the tokens each top example's peak attends to and the head's previous-token, duplicate-token and induction scores (Olsson et al., 2022); heads get no vocabulary lens or partner search. Head commands load the model with eager attention. Head pages live at `models/<model>/L<layer>/H<idx>.html` and in `wiki/experiments/<model>/L<layer>/H<idx>/`. Parquet gains `kind`, `head_idx`, `model_n_heads` and the three pattern scores (`neuron_idx` and `pole` are null for heads), and the home page counts heads studied. The decision rule for neuron poles is unchanged, but every existing verdict was judged under 0.5, so `openinterp next` now proposes re-evaluating them. A positive-control dry run on GPT-2 small L5H1 scanned 235,650 tokens in about 2 minutes on CPU (induction score 0.89) and the proposer identified it as an induction head unprompted. It was NEEDS_REVISION after two rounds, on specificity alone (see TODO).
- **Explanation scores on held-out text** (Delphi; Paulo et al., 2025), reported, not gated. `openinterp score` cuts the corpus snippets the proposer never saw (everything but the scan's top examples) into 32-token windows. It measures each window on its own, as the judge reads it, and draws active windows evenly from 5 activation bins, plus inactive ones. Three scores:
  - *detection:* a judge given only the explanation picks the windows that activate the pole;
  - *fuzzing:* the judge decides whether the marked tokens in a window are the ones that activate it;
  - *embedding:* the AUROC of explanation–window cosine from a local sentence encoder (`sentence-transformers/all-MiniLM-L6-v2`), with no LLM.

  The judge is a LiteLLM model, or two-step: `--emit-task` writes the windows and two prompts (no activations), and `--task` scores the answers. The new `explanation-judge` subagent answers in Claude Code. **Every review records them.** `review --probes` requires `--explanation-scores`, and a one-step `review` scores the explanation itself on `--corpus`, with `--judge-model` defaulting to the reviewer. `reevaluate` stays LLM-free, so `--explanation-scores` is optional there. When no held-out window is active, detection scores false positives only and fuzzing is skipped, so scoring never blocks a review. Both commands record them as `VerificationVerdict.explanation_scores` (`ExplanationScores`, optional, so older records validate). `openinterp reproduce` re-measures the windows and re-derives the scores from the stored answers, warning on differences. Experiment pages gain an *Explanation scores on held-out text* section. It has tiles for the three scores, detection recall per activation bin, and the judged windows as token heatmaps, with the explanation's misses and false alarms first and fuzzing marks dashed. `make sample-run` includes synthetic scores. Parquet gains `detection_score`, `fuzzing_score` and `embedding_auroc`. Scoring takes about 2 minutes on CPU for Qwen2.5-0.5B. On L1/N12− (VERIFIED, a bigram detector), only 69 of 4000 held-out windows were active, and a literal reading of the explanation found none of them. Its held-out activity is mostly ` in` after verbs other than *look*, which top examples alone don't show.
- **Windowed scans:** `openinterp audit --window-tokens N [--stride S]` scans each document as overlapping N-token windows that start every S tokens (default N/2), instead of whole. Long documents are read in full, and the scan's top examples become windows rather than whole documents. Each token counts once in the histogram, confound profile and partner search: in the first window, or else in the fresh tail of the first later window that reaches it, so it has at least N − S tokens of context. Top examples never overlap, and they are decoded back to text, so `reproduce` re-measures them exactly as the scan did. On Qwen2.5-0.5B, a 256/128 scan counts exactly the tokens a whole-document scan does. Provenance records `snippet_tokens` and the new `snippet_stride`, and experiment pages show them. The vocabulary lens then reads each of the first 100 documents' first window. `openinterp score` now holds out every document that contains a top example, not only exact matches. Whole documents stay the default, so existing scans are unchanged.
- **Experiment costs**, reported, never gated. Every record stores what its experiment cost in `submission.provenance.costs` (`ExperimentCosts`, optional, so older records validate). That is wall time per stage (`model_load`, `scan`, `lenses`, `proposer`, `counterfactuals`, `heldout_windows`, `judge`, `embedding`, `remeasure`, `reviewer`, `probe_measurement`, `gates`, `causal_metrics`) and, per LLM call, the model, attempts, prompt characters, prompt/completion/cached tokens and cost from LiteLLM (read through an instructor response hook, summed over retries). The two-step flow carries costs through its files: evidence → submission, score task → scores → record. A prompt answered from a file is timed from the prompt's mtime to the answer's, with no token counts. Re-reviewing a record or re-evaluating it records only the new run's costs. Experiment pages show a *Run cost* line. With `OPENINTERP_COSTS_LOG=<file>` set, every `openinterp` command (including `check`, `wiki` and `build`) appends its wall time, stages and LLM calls to that JSON-lines ledger, and the new `openinterp costs <ledger…> [--session <file>]` summarises ledgers and `claude -p --output-format json` results. `scripts/experiment-loop.sh` now runs sessions with `--output-format json`, keeps a ledger per experiment in `logs/loop/`, and prints each experiment's cost and a running total. Tests clear `OPENINTERP_COSTS_LOG`, so `make test` inside a loop session doesn't add to it. `make test` and `make lint` are not timed separately; they fall under the session's wall time.
- **Probe results chart** on experiment pages, above the adversarial review table. Every hard negative and positive holdout is a dot on one pole-strength axis, with the reviewer's threshold (`activation_threshold` × max activation) drawn as a line and the active side shaded. Passed probes are green dots and failed ones red crosses, so pass/fail never relies on colour alone. Dots at the same value are dodged vertically rather than hidden, and hovering one shows its strength and prompt. The axis extends past the scan max when a probe exceeds it. It is static SVG rendered at build time, like the histogram; the values stay in the table below. Records without a recorded policy or max activation show the table only.
- **`c4` corpus preset:** `openinterp corpus --dataset c4` samples the English validation split of [C4](https://huggingface.co/datasets/allenai/c4) (`allenai/c4`), the web baseline much of the SAE literature uses. C4's main branch is gzipped JSON, so the preset reads the Hub's Parquet conversion (`refs/convert/parquet`, `en/partial-validation`); presets can now name a default `revision`, and `--revision` still overrides it. That branch has no dataset card, so when the pinned revision has none, the licence comes from the default branch's card (ODC-By here). 500 documents take about 40 seconds, and rebuilding at the recorded commit gives a byte-identical corpus.
- **`land-experiment` skill:** `choose-next-experiment` plus building the site, waiting for CI to go green and merging the PR. It merges only when every check passed on the current head, the PR touches nothing outside `wiki/`, and the agent's `gh` account has write access; otherwise it comments on the PR and moves on to the next experiment.

### Added

- `openinterp corpus`: samples a scan corpus from a Hugging Face Parquet dataset without downloading all of it, by reading seeded random row groups over HTTP. Presets: `fineweb-edu` (`HuggingFaceFW/fineweb-edu`, sample-10BT; the default) and `pile-10k`, or any dataset with `--files`. It writes `corpus.jsonl` and a `corpus.source.json` sidecar (`CorpusSource`: dataset, commit, files, seed, sizes, licence, SHA-256). Audits record the source in `provenance.corpus_source` when the corpus still matches it, and experiment pages show the licence. The same seed and revision rebuild a byte-identical corpus. Replaces the README's Pile snippet.
- **Attention heads, step 1: identifiers and hooks.** `ComponentIdentifier` is a union of `NeuronIdentifier` (`kind = "mlp_neuron_pole"`, the default, so existing records validate unchanged) and the new `HeadIdentifier` (`kind = "attn_head"`, `head_idx`, slug `L<layer>/H<idx>`). `NeuronHookRunner` resolves each layer's attention output projection (Llama/Qwen/Mistral/Gemma/Phi, GPT-2, GPT-NeoX, GPT-J, OPT, Falcon) and gains `head_outputs`, `head_write_norm`, `head_output_weights`, `attention_patterns` and `hooks(head_interventions=…)`, plus `ablate_head`. `_load_runner` takes `attn_implementation` (patterns need `"eager"`). Submissions still accept neuron poles only and reject a head with a clear message, so the decision rule and `PROTOCOL_VERSION` are unchanged.
- **Most recent experiments** on the home page: the latest 10 experiments, whatever their verdict, newest first, with review time (UTC), neuron, status, evidence strength, hypothesis, proposer and reviewer, and a tag for re-measurements. On small screens the date moves under the neuron.
- **Proposer and reviewer as Claude Code subagents, with no API key.** `.claude/agents/neuron-proposer.md` and `neuron-reviewer.md` answer prompt files. The reviewer has no tool that runs the model, so it can't see probe activations before its probe set is final.
- Two-step CLI commands that write a prompt and exit, then take the answer as JSON, so no process waits on an answer file: `openinterp audit --evidence-out` (scan evidence as `ScanEvidence` JSON plus the proposer's prompt), `audit --evidence … --hypothesis …` (builds the submission without rescanning), `review --emit-prompt` (loads no model) and `review --probes …`. `--agent-model` is required with an answer file, so the record names the model that wrote it.
- `scripts/experiment-loop.sh`: for `external/<name>` models the driving session now uses the subagents.
- CI job **Reproduce records**: runs `openinterp reproduce --base-ref origin/<base>` on every pull request, on CPU, with Hugging Face weights cached between runs. Only models in its `ALLOWED_MODELS` are loaded (`openinterp reproduce --allow-model`). Failures appear as file annotations and in the job summary.
- Auto-signing: `verify`/`review` and `reevaluate` sign each new experiment record when the machine holds a signing key (`~/.ssh/openinterp_signing` or `$OPENINTERP_SIGNING_KEY`) that is listed in `.github/allowed_signers`, so a maintainer's own runs and experiment loops skip CI reproduction. `OPENINTERP_AUTO_SIGN=0` turns it off.
- `openinterp sign`: a maintainer vouches for experiment records with an SSH key (`ssh-keygen -Y sign`), writing `<id>.json.sig` next to each record. `reproduce` skips records signed by a key in `.github/allowed_signers`, read from the base branch under `--base-ref` so a pull request can't trust its own key, and fails on a signature that doesn't verify. `openinterp check` flags signatures whose record is missing. A signature doesn't change the verdict.
- `openinterp reproduce`: re-runs a record's scan evidence, counterfactual deltas and review against the model commit and dtype it pins, under its own policy and with no LLM calls. It fails on any number outside tolerance (`--atol` × scale + `--rtol` × |recorded|) and on any differing pass/fail, gate or status. `--base-ref` picks every record a branch adds or changes.
- `RunEnvironment` (device, weights dtype, model commit, openinterp/torch/transformers versions) is recorded on every verdict and on the scan's provenance. The model commit is now resolved from the Hugging Face cache, because `config._commit_hash` is empty in recent transformers: five of the seven records in the registry have no `model_revision`. `_load_runner` takes a `revision`.
- `ActivationPatcher.patch_many`: patch many neurons of one layer, one per batch row, with any effect function (`metric_change`, `next_token_kl`). `logit_direction_metric` scores logits along a centred vocabulary direction.

## [0.0.3] - 2026-10-18

Ships with protocol version **0.4**.

### Added

- `scripts/experiment-loop.sh` (`make loop`): runs experiments back to back in fresh headless Claude Code sessions, in a separate worktree reset to `origin/main` each time, until `--max` or until `claude` fails (for example at the usage limit). `--proposer` and `--reviewer` choose the LLMs; `--driver` chooses the Claude model driving the session. Logs go to `logs/loop/` (git-ignored).
- `NeuronAuditSubmission.model_mlp_width` (neurons per MLP layer), recorded by the proposer and exported to Parquet. It is optional, so existing records still validate.
- `--agent-model external/<name>`: any LLM, agent or person can act as proposer or reviewer by answering `exchange/<Agent>.prompt.md` (which includes the JSON schema) with `exchange/<Agent>.response.json`. No API keys are needed.

### Changed

- **Experiments, not neurons, are the unit of storage.** `audits/` is retired: each experiment's write-once `wiki/experiments/<slug>/<id>.json` is the only source of truth, so a neuron can have any number of experiments and parallel PRs on one neuron no longer collide. `verify` and `reevaluate` add a new experiment and never overwrite one (`--out` writes an optional extra copy). `openinterp check` drops the one-record-per-neuron rule, checks each record's path and page instead, and rejects records left in `audits/`. The planner derives each neuron's state from all of its experiments. `openinterp wiki --audits-dir` becomes `--import-dir`, and `check`/`next` lose `--audits-dir`.
- **Protocol 0.4:** `independent_review` is recorded but no longer gated by default (`ReviewPolicy.require_independent_review = False`).
- Site coverage now counts neurons rather than layers: model cards and pages show neurons studied and neurons with a verified pole, each out of the model's total neurons (layers × MLP width). Before, one experiment anywhere in a layer counted the whole layer as covered. Records without a width fall back to `KNOWN_MLP_WIDTHS` in `builder/tree.py`; when the width is unknown, the total shows as "?".

## [0.0.2] - 2026-10-18

Ships with protocol version **0.3**.

### Added

- README "Get started" guide for contributors: setup, API keys for an independent proposer and reviewer, building a Pile scan corpus, running an experiment with Claude Code or by hand, and claiming and posting it as a PR. `submissions/` and `corpus.jsonl` are now git-ignored.
- **Protocol v0.3: covariance and confounds.**
  - Near-duplicate probes cluster into single observations (`core/stats.py`). The probe-count gates, balanced accuracy and significance use these effective counts.
  - The scan (`harness/scan.py`) gathers in one pass the top examples, the most correlated same-layer neurons (`harness/covariance.py`) and a confound profile: token-identity and position R², frequency correlation and trigger tokens (`harness/confounds.py`).
  - New gate `beats_confound_baseline`: the hypothesis must match or beat token-identity, position and never-active baselines on the reviewer's probes.
  - Joint ablation of the pole with its correlated partners, reporting a redundancy ratio (recorded, not gated).
  - Re-measurements of an earlier probe set are marked as not independent, rank after the original, and are excluded from the most-conclusive list.
  - The home page estimates expected false discoveries among VERIFIED claims.
  - Neuron pages summarise both poles together.
  - The proposer sees the confound profile and correlated neurons.
- **Jacobian lens** (`harness/jlens.py`; Gurnee et al., 2026, arXiv:2607.15495).
  - Reads each pole's output direction through both the context-averaged Jacobian lens and the logit lens, and records `submission.vocabulary_lens` (both token lists, overlap, cos(w, J·w), kurtosis).
  - Estimates J·w from one perturbed forward pass per prompt and sign. Tests check it against exact autograd on Llama-style and GPT-2 models.
  - On Qwen2.5-0.5B the two lenses share 0/10 tokens up to the middle layers and converge only near the output.
  - Shown on the site and wiki, exported to Parquet, fed to the proposer; the vocabulary skill now defaults to it.
- **Rank-based and regime-aware correlation.**
  - Frequency correlation is Spearman's ρ (tie-aware, exact).
  - Partner neurons are found per *pole* by co-activation lift (`PartnerSearch`): a fixed-seed reservoir sample plus the target's top tokens, with chunked Spearman and Pearson kept for reference.
  - Partners are ranked and selected by the 95% Wilson lower bound of the lift, which the new `min_partner_lift` and `min_partner_coactive` policy fields govern.
  - Global Pearson missed real partners: on L11/N4255 every |r| was below 0.07, while co-activation lift was at least 10.
- Every experiment is published, null and superseded results included. The site follows Model → Layer → Neuron → Experiments, with model and layer index pages, and each neuron page lists all experiments on both poles.
- Experiments are ranked by *conclusiveness*: the posterior probability that balanced accuracy exceeds 0.6, folded to |2P − 1|, so strong evidence ranks high in either direction (`builder/significance.py`). The home page features the most conclusive results in both directions.
- A write-once experiment archive: `wiki/experiments/**/<id>.json` stores each experiment's full record next to its page. `openinterp check` validates it and rejects edits to it.

### Changed

- `openinterp build` reads the wiki archive (`--wiki-dir`) instead of `audits/`, and `--include-unverified` is gone because everything is published.
- `registry.parquet` has one row per experiment, with `experiment_id`, `is_latest`, `p_useful`, `conclusiveness` and `evidence_direction`.
- Neuron pages moved from `neurons/<slug>.html` to `models/<model>/L<layer>/N<idx>.html`.

## [0.0.1] - 2026-10-18

First release. Ships with protocol version **0.2**.

### Added

**Harness and protocol**

- Strict Pydantic v2 schemas for neuron identifiers, counterfactual pairs, lookahead profiles, causal metrics, submissions, verdicts and audit records.
- `NeuronHookRunner`: hooks on MLP down-projection inputs for Llama/Qwen/Mistral/Gemma, GPT-2, GPT-NeoX, GPT-J, OPT and Phi, with positive/negative pole isolation and corpus scanning.
- Activation patching: denoising, noising and resample ablation per pole, with optional freezing of downstream MLP outputs to mitigate self-repair.
- Attribution patching for whole layers in one backward pass.
- Lookahead profiling (pole-ablation KL and concentration) and vocabulary projection of neuron output directions.
- `ProposerAgent` and `ReviewerAgent` using LiteLLM and instructor (default model `anthropic/claude-opus-5-5`). Verdicts are computed deterministically by `evaluate_submission`.
- Protocol v0.2 (`docs/PROTOCOL.md`): a gated decision rule using balanced accuracy over hard negatives and positive holdouts, a counterfactual tolerance relative to the prediction, minimum probe counts and an independent-review gate. It replaced v0.1's weighted mean and absolute Δ tolerance of 0.35 before release, after v0.1 verified an over-broad hypothesis.
- Experiment provenance on submissions (model revision, corpus hash, selection method, seed) and the review policy stored on verdicts.
- CLI commands `audit` (including `--random --seed`), `verify`/`review` (which also accepts an existing audit record), `reevaluate`, `build`, `deploy`, `wiki`, `check` and `next`.

**Registry, wiki and site**

- Experiment wiki (`wiki/`): a write-once Markdown page per completed experiment, with per-neuron history pages and a home index. `verify` and `reevaluate` write pages automatically, `reevaluate` saves the superseded verdict before overwriting a record, and `openinterp wiki` backfills existing records.
- `openinterp next` and the `choose-next-experiment` skill: a randomised next-experiment planner (ε-greedy exploration of random neurons, Boltzmann sampling over follow-ups, decay for repeats, recency and open-PR claims). It prints a seed for reproducibility.
- Static site builder (Jinja2 + Tailwind) with per-layer coverage, leaderboards, Pagefind search and a DuckDB-Wasm SQL console. The registry is exported as `registry.parquet` plus content-addressed snapshots.
- The build is deterministic. There are no build timestamps, orderings are total, and stale pages are removed, so unchanged records rebuild byte-for-byte.
- Cloudflare R2 delta sync with per-file cache policies:
  - content-addressed files upload first and HTML last;
  - `pagefind/` only syncs when a source file changed;
  - `data/snapshots/` is never deleted;
  - an optional Cloudflare cache purge covers only the changed URLs.

**Project infrastructure**

- GitHub Actions CI: lint, a 500-line limit on source and documentation files, tests, and `openinterp check` (audit/wiki pairing, stale indexes and write-once pages) on every PR.
- Hourly deploy workflow that rebuilds from `main` and delta-syncs to R2. It is skipped until the `R2_BUCKET` variable is set.
- A PR template with an experiment checklist.
- Ten Claude Code research skills in `.claude/skills/`, each grounded in the interpretability literature.
