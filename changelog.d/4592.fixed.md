- The deploy's site build runs under a 13G memory cap (`scripts/capped.sh`). Above the cap, the kernel kills only the build, and the step fails at once with an out-of-memory error. Before, a build that ran out of memory killed the runner agent too, and the run hung for about 45 minutes with no reason in its log. The step prints the total peak memory of the build and its workers, and warns above 11G. The build's forks now run under `gc.freeze()`, so each worker shares more of the parent's memory (#4592).
