## Hypothesis

> Retrospective lexical-field detector for computing-systems text, dominated by cryptocurrency/blockchain vocabulary and the C-family source code that implements it: it fires on the current token when that token is a crypto term (blockchain, bitcoin, wallet, miner, ledger, block, chain, transaction, hash, signature, proof, token, satoshi, merkle, node, peer, consensus, 0.4-0.9 of the 3.885 max), a C-family declaration or hash/header/licence token (const, static, unsigned, uint, struct, template, namespace, private, public, '<', '>', sha256/'256', digest, License, Copyright, VERSION, headers, 0.15-0.7 of max), or vulnerability-advisory vocabulary (buffer, overflow, length, field, attacker, valid), with about half the input attribution on the peak token itself and a short carry-over to the next few tokens. Its activity is set by context as well as by the token: in a sustained crypto/software sentence even surrounding ordinary words cross the 0.25x activity line (' of' 1.24, ' system' 1.35, ' party' 1.12, ' replaced' 1.09) and the same token fires or not depending on its frame (' address' 2.37 after 'a new' with bitcoin but 0.00 after 'a new' with parcel; ' block' 3.62 after 'hash of the' with miner but 0.11 with builder), whereas the same words in everyday senses (food chain, dinner fork, swimming pool, car key, private life, driver license, television network, coal miner, the ship's ledger, 'the size of the shoe') stay at 0.00-0.56, and ordinary prose, non-computing technical writing (electrical datasheets, medicine, astronomy, law, mathematics) and generic code with no systems/crypto vocabulary (Python loops, JavaScript, SQL, a plain C loop) read 0.00-0.76; computing-security words outside its set (password, login, username, malware, phishing, ransomware) also read near zero. Its output direction leans the same way (Jacobian lens: ' bitcoin', 'BTC', ' satoshi', 'ertodd'), but it predicts no single upcoming token: the ablation profile is diffuse and fails the lookahead concentration gate, and 49% of the input attribution sits on the peak token itself.
