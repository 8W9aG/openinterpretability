**Latest status:** VERIFIED (2026-10-20)

> The negative pole fires on a standalone operator glyph that is being used as an operator inside a symbolic expression: strongest on the space-prefixed plus ' +' and its LaTeX form '+\' (e.g. $a + b$, \kappa_{\mathrm{ex}}+\kappa_{\mathrm{in}}, 3 + 4, x = 42; y = x + 1;, f(a) + g(b)), then on ' -' and ' ='/'=\' at roughly a third to a half of that strength, with strength graded by how formulaic the immediate context is (highest inside $...$ math and backslash-command neighbourhoods, lower when the same expression is embedded in ordinary prose). It stays near zero when the glyph is not an operator of an expression: fused into a word, identifier, e-mail or URL ('C++', 'a+b', 'john+tag@example.com', 'h=315'), replaced by non-operator punctuation (a comma between the same operands), a lone LaTeX command or backslash, narrative or programming-discussion prose ('The story a + b is here.', 'In Python, a + b works.'), or another operator glyph (*, /, <, >, ^, ==, !=), which fire at most weakly (peak <= ~0.75, below the active range); it is a formula-operator detector, not a general symbol, punctuation or LaTeX detector.
