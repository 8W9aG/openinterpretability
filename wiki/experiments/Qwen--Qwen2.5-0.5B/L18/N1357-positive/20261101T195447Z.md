The scheduler distributes runnable tasks across the available cores, and the load balancer periodically re-evaluates each run queue to keep the distribution reasonably even. When a task wakes from sleep it is placed on the queue of the CPU it last ran on if that queue is not already saturated, which preserves cache locality at the cost of a small imbalance that is corrected on the next balancing interval. The interval itself is derived from the number of online CPUs and the current utilisation, so a machine that is mostly idle rebalances far less often than one running a parallel build.

Memory reclaim follows a similar pattern. Each memory cgroup maintains its own least-recently-used list, and the reclaimer walks that list from the tail, writing back dirty pages before evicting clean ones. Pages mapped into more than one address space are placed on a separate list and are only reclaimed once the active and inactive lists have been exhausted, because evicting a shared page requires updating every page table that references it. The watermarks that trigger direct reclaim can be adjusted per zone, and raising them too far will cause unrelated allocations to stall behind the reclaimer for tens of milliseconds.

Interrupt handling is the part that surprises most people. A device interrupt is acknowledged by the local APIC, the handler runs in hardirq context with interrupts disabled on that core, and any work that cannot be completed quickly is deferred to a softirq or to a threaded handler. Long handlers therefore show up as latency spikes in unrelated workloads, and the usual fix is to move the interrupt affinity away from the cores that run the latency-sensitive thread. If the driver supports it, enabling threaded interrupts is usually cleaner than pinning.

Tracing works through a ring buffer sized in pages, where each event record carries a timestamp, a type and a payload whose layout depends on the tracepoint. Writing a large number of events from a hot path will overflow the buffer and silently drop records unless it is configured to block producers instead, which trades latency for completeness. Most people discover this only after generating a trace that looks plausible but is missing the interval they actually wanted to inspect.
