## Hypothesis

> The pole is a layer-0 unigram (token-identity) detector: its strength is set by which token is being read, not by context or position (token identity explains 90% of the variance, position 1%), and it never fires on the frequent core of the vocabulary, staying at zero for function words, common content words and common names ('the', 'people', 'time', 'white', 'John', 'Paris' all measure <=0.06, and in the scan no token appearing 100+ times reaches the active threshold). It fires only on a sparse, idiosyncratic subset of the low-frequency long tail - rare words ('picnic', 'apartment', 'purple', 'blond', 'notebook'), proper names and places ('Sarah', 'Barbara', 'Rwanda'), technical and code/markup identifiers ('Npgsql', 'DataTable', 'dataGridView', '.md', '.rs') and unusual word pieces ('elix', 'oton', 'ologist') - and because many equally low-frequency words ('canyon', 'automobile', 'cuisine') stay at zero, predict active only when a marked long-tail token of these kinds is present, and inactive when every token is frequent core vocabulary.
